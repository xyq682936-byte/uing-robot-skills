# 机械臂并行直接控制

公开版本：0.1.5；作者：Uing；许可：MIT（范围见包内 LICENSE 与 README）。

目标：在用户指定的测试条件和真实仿真物理约束下，由 agent 观察、决策、执行短段动作，尽可能找到不同的有效抓取策略；执行时采集原始数据，登记并复核成功；完成整批策略筛选后，才对已复核成功策略单独提炼、优化和复跑。

本技能中的 agent 指承担判断与控制工作的智能体，不绑定特定模型或产品。不承诺仅靠改变控制方式就一定提高成功率。

本包提供执行规则及本地成功数据打包/回传辅助模块；源码仓库另有合成测试。不包含通用 Isaac 控制器、预算调度器、物理验收器或自动安装器。运行前核实已有接口及实际实现，不能以技能文件存在代替功能接入。规则与仿真闭环在用户本地执行，不依赖发布服务器远程加载规则或控制动作。上传默认关闭；接入状态和未完成项见 [部署与接入边界](references/deployment-status.md)。

**每批开跑前快速复读**：每次开始新的批量训练，包括连续多轮中的下一批，以及中断后重新开跑，agent 都须重新查阅实际加载的当前 `SKILL.md`，并按本轮模式读取必要引用，核对本轮配置和关键限制。不能因同一对话、刚跑过上一批或记得旧摘要而跳过；以简短记录留存读取的版本、批次和检查结果。复读不要求用户重复授权，不编写长篇预习或整批固定轨迹，详见 [每批开跑前快速规则复核](references/parallel-runtime-and-demo.md#每批开跑前快速规则复核)。

## 1. 适用范围与配置来源

- 面向 Isaac Lab / Isaac Sim 仿真。阅读、安装和修改本技能不授权启动训练；仿真授权不等于真实机器人运行授权。
- 用户当轮明确要求优先于本技能默认值。默认建议为 **40 臂同步、每物品 200 个策略机会、每个策略机会最多 3 次实际抓取失败**。每次新训练须通过自然沟通确定物体、机会预算和并行臂数；允许用户委托 agent 在已授权库中挑选未训练物体，或按已有记录继续；不能把建议值当作用户已授权的执行值。这些是可调整的配置，不是程序写死的限制。
- 将工作模式与切换依据、物品清单、机械臂分配、预算模式、额度、逐物品成功策略停止数量与计数范围、有效标准、存档根目录及恢复状态写入唯一的本轮配置。正文说明、界面提示和执行程序都读取该配置；某轮的临时参数不能改写成通用默认值。
- 旧程序中的物品清单、数量和历史验收标签，不限制用户已授权的新任务。优先复制到独立工作目录或做必要适配，保留原始文件。真实的关节、驱动、碰撞、载荷和接口限制仍然有效。
- 不自动启用历史测试文件或其他旧标准。只使用用户本轮选择的有效标准；历史轨迹可以作为策略检索资料。

## 三种同级工作模式与长期目标

- **探索模式**：面对未知物体、新操作或已有策略实际失败，在有效标准、预算与控制边界内直接进行短段接近和接触，依据现场反馈持续提出并检验抓取部位、通道、姿态或操作顺序等假设；不先准备长篇文本、虚构数据或固定整条轨迹。X 取用户确认的臂数，各臂采用不同策略并持续监管。按 [探索与操作经验规则](references/exploration-mode-and-experience.md) 积累动作片段、失败边界和组合操作关系。
- **优化结果模式**：整批探索结束并复核后，使用所有相关成功机械臂的实际数据，按策略和条件分组，反向提炼、二次复现并优化等待及动作时间；新版本复核成功后存入原库的“成功库/优化结果”独立文件夹。可按已允许的空闲优化规则或用户批准批量执行，必须有限、可恢复；已复训完成的策略明确标记并跳过，不能重复复训。详见 [优化结果模式](references/success-replay-and-acceleration.md)。
- **实际场景模式**：等待用户调用既有成功策略，在具体姿态、障碍或多步任务中执行与验证；失败后总结原策略及失败环节，保留有效部分，回到探索模式开展针对性探索，再验证原失败场景并保存成功分支。这不算重复复训，也不清除已优化标记。详见 [实际场景与针对性探索](references/actual-scene-mode.md)。

整体链条：探索成功并整批收尾 → 优化及新复核成功 → 保存并等待用户使用实际场景模式 → 场景失败时总结原因、基于原策略针对性探索 → 原失败场景复核成功并保存。场景直接成功则按实际范围归档；恢复成功不自动追加优化或新预算。

优化产物用于后训练保存、现实操作的策略建议和经验记忆，支持未来其他 agent 学习安排机器人操作；长期目标是对话驱动具身系统探索未知交互和复杂组合任务。保存经验不等于更新模型权重，单动作成功不等于组合或真机已验证。当前技能仍只直接执行获授权的仿真任务；模式、切换原因和任务身份写入配置，续跑不能静默换模式或重发预算。

## 2. 首次配置与每轮确认

“首次安装核验”与“首次训练配置”分别处理。安装、加载异常、首次使用或更新后，按 [首次安装与加载核验](references/standards-and-setup.md#首次安装与加载核验) 确认宿主、实际加载位置及版本；仅复制文件不等于宿主已发现或 agent 已读取。初始化指当前用户、项目和运行环境没有有效配置；新开对话或技能升级不重建原库。仅安装时核验安装并交付后续入口，不启动仿真；用户要求初始化或使用时继续补齐所需信息，已明确项和授权直接沿用。标准变化仍按 [标准与配置规则](references/standards-and-setup.md) 处理。

**训练前与用户确定目标、策略机会次数和同时运行的机械臂数量，不要求用户会专业术语或填写固定表格。** 目标可通过聊天描述确定，也可提供名称、模型路径、附件或资产编号；用户可说“从未训练的物体里找一个”委托 agent 在已授权的库中选择，或说“继续”恢复明确的已有任务。agent 负责把自然表达和已有记录对应到实际资产与运行配置，不要求重复提供能查到的路径。只补问无法可靠确定的信息；没有已有有效值时不静默采用默认 200/40。选择未训练目标不等于把全部模型开跑；续跑不重发预算、不清零失败，也不重新启动已完成任务。具体见 [训练启动信息](references/standards-and-setup.md#每次训练的启动信息)。

首次实际执行前，用卡片收集以下内容；平台不支持卡片时，用等价的简短文字选项：

1. **仿真环境**：先询问用户选择的仿真训练软件、版本要求及运行位置；用户已明确指定时沿用。本技能现有控制流程面向 Isaac Lab / Isaac Sim，其他环境须先核实适配能力，不能只改软件名就声称支持。
2. **检索授权**：是否允许检查本机性能配置及所选软件、版本、依赖和运行环境。仅检查任务所需范围；未授权时使用用户提供的信息，标明能力尚未核实。
3. **存档位置**：由用户指定根目录，确认归档规则，默认推荐“按日期归档”。已有当日目录时复用，在其下建立唯一批次目录。
4. **验收依据**：用户采用的标准或项目验收条件、参考文件位置及版本。
5. **模型来源**：可先通过聊天描述物体，再由 agent 在已授权的模型库、历史登记或当前任务中定位；也可由用户直接提供名称、路径、附件、资产编号或库入口。委托代选与“继续”按启动信息规则处理，能从已有记录确定的技术信息不让用户重填；确无可访问资产或存在影响选择的歧义时才补问，不猜测或扫描无关个人目录。

导入模型时读取 [用户模型接入、评估与副本转换](references/asset-intake-and-conversion.md)。结构或碰撞异常时按 [模型结构与碰撞修复](references/asset-intake-and-conversion.md#模型结构与碰撞修复) 区分功能孔洞与生成破损；不为水密一律封口，优先只修失真的碰撞，保留未涉及的形状和物理参数，并用实际加载及必要接触/通道证据核实。碰撞体误堵空隙时，按 [内存修正与询问](references/asset-intake-and-conversion.md#碰撞体误堵空隙的内存修正与询问) 提供“同意本次／本轮同类都同意／暂不修正”，获准后仅改临时内存实例，保持质量/摩擦等有效参数并将修正前后分开统计；本轮授权只在明确范围内沿用。资产库先核实接口及使用规则；文件先评估是否满足本轮仿真条件。需要转换或修复时说明碰撞、法线等实际缺口并询问是否辅助处理。源文件保持不动；转换前先复制到用户指定库内，再为复制文件建立独立备份并校验，随后只修改工作副本。库内设置“用户模型文件复制”，其直接子目录“已转换好”仅存放转换及必要接入验证完成的版本。

检查发现本机缺少所选软件或配套环境时，询问用户是否需要自动下载程序并搭建可直接开始训练的环境；先说明可执行的配套方案、版本、安装位置、主要下载/空间需求和必要系统变更。获得相应授权后，连续完成下载、依赖配置、启动入口和最小就绪检查，减少重复操作；按 [环境选择与自动搭建规则](references/standards-and-setup.md#环境选择与自动搭建) 执行。不能把安装完成等同于可训练，不能因本次仅修改技能就开始安装或仿真。

检索后给出并行能力估计，区分“场景内同时仿真的数量”和“当前画面可见数量”。估计不能冒充实测上限；在已授权的运行范围内用代表性场景核实。机器、场景或环境版本变化后重新核实相关能力。

**每批开始测试新物体前，用同一卡片确认机会预算和成功策略停止数量。** 询问“每个物品最多测试多少个策略机会；在额度内累计获得多少个已复核的不同成功策略后，停止该物品探索并转向下一物品？”预算默认显示“每物品 200 个策略机会”，并区分每物品额度与整批共享额度；停止条件可填写正整数 K，或明确选择“跑满机会额度，不按成功数量提前停止”。可以整批采用同一 K，也可逐物品设定，记录适用物品。用户在本次请求中已明确给出的值直接记录，只询问缺项；不能替用户猜 K，预选项、沉默或等待超时不算确认。

停止计数默认采用本批、该物品当前版本下，按既定抓取成功条件完成复核的独立策略数；重复试次、微调和未复核候选不重复计入。用户要求以完整标准通过为停止依据时，按该范围计数。成功目标不改变验收判据，不自动纳入旧批次成功记录。恢复同一中断批次沿用原目标、已确认成功集合和剩余额度，不重新发放机会或重复询问；追加与新建批次分别记录。详细的并发停止和预算处理见 [策略与预算规则](references/strategy-and-budget.md)。

每轮策略开跑前，可在已有确认中附带询问用户是否有参考思路；某物体完成本轮并完成适用复核、独立成功数为零时，也可结合失败摘要询问。允许用户随时补充规则、图片或针对物体的策略，不按专业程度判定质量；参考思路是可选项，用户没有思路时在已有授权内继续，不反复阻塞多臂。按 [用户补充与评估](references/user-contributions-and-review.md) 保存原文、明确范围、检查冲突和实际动作差异，初评与实跑证据分开；新建议不自动追加预算。

同时明确物品编号、并行臂分配、可观测成功条件，以及标准要求的有限验证次数。没有额外复测要求时不自动启动无限复测，单次探索成功如实标记。

操作开始前给出有依据的大致用时范围和主要不确定因素；没有实测依据时说明暂不能可靠估时，在首个代表性运行片段后更新。不要把大量预写动作文本当作准备工作。

## 3. 标准先落实，结果后复核

需要区分抓取成功、后续性能加载与整批结束时，读取 [分阶段验证规则](references/staged-verification.md)。

- 将有效标准中适用的环境条件、测试程序、测量指标和判据落实到仿真。检查实际运行参数、传感器响应和记录链路；只生成文档或配置不算落实完成。
- 区分标准原文、仿真适配、项目自定参数。不得自造统一“美国标准合格线”，或把局部方法验证描述为完整认证。
- 最终验收在数据形成后进行，但所需条件和测量必须提前确定。“最后对照标准”是用真实数据复核，不是只比较两段文字。
- 用户引入新标准时，先选择“封存旧标准并替换”或“叠加标准”。保存原文、比较条款、处理冲突后再启用。具体规则见 [标准与配置规则](references/standards-and-setup.md)。
- 每段操作都应在当前有效规则内寻求成功，不能通过减小质量、提高摩擦、改变夹爪能力或放宽判据来掩盖失败。允许的环境随机化和参数调整必须有已记录的依据。

## 4. 策略差异检查与物理可行性

执行前读取 [策略与预算规则](references/strategy-and-budget.md)，为每个物品建立候选策略表，并与本轮及历史策略比较。

用户追加策略机会时，必须先核对同物品已有成功、失败、微调、历史候选和当前队列，确认追加方案与此前策略及追加队列内部均不重复，再派发新增机会。核查重点是动作策略及其推演，不是名称、编号或参数差值：在物体坐标系下，对照最相近旧方案的接近路径、夹持/承力接触、阶段顺序、物体姿态变化和反馈调整。推演只需阶段与关键动作关系，不预写整条固定轨迹。

新独立策略须至少在接触/承力关系、实质接近通道或操作机制/阶段安排中有一项明确变化，且能说明该变化怎样改变关键动作与约束。单纯小幅调整角度、位置、速度或夹力仍是原策略微调；大角度变化也不自动构成新策略，不设一个通用的角度及格线。说不清实质区别、历史证据不足或执行后发现实际动作同质时，不计为新独立策略，详见 [动作差异判定](references/strategy-and-budget.md#动作策略差异的判定标准)。明确授权的旧策略复测/微调另行有限安排，不混入追加新策略额度。

- 表中描述抓取部位、相对物体的接近方向、夹持方式、动作阶段和反馈调整思路；不提前写死完整动作轨迹。
- 只改编号、名称，或小幅修改位置、角度、速度、力度，不构成新独立策略。微调关联原策略，不能凑机会数或成功方案数。
- 先识别主体、拉手、边缘、凹槽、凸起、连接处等结构，结合夹爪、碰撞模型及可达空间，分别评估部位、两指接触关系和接近通道。单一方向受阻、一次失败或局部失真不能排除整个部位；有依据的候选有限实跑，排除须有具体证据，尚未检查标为未探索。重复同类失败时先复核模型、接触、通道和执行，再决定微调或转向。两指描述适用于双指夹爪，其他末端按实际接触/承力机制记录，详见 [抓取覆盖规则](references/strategy-and-budget.md#抓取部位与接触方式及方向覆盖)。
- “物品的每一寸都可以尝试”表示不预先排除其他部位，不要求在有限额度内穷举连续表面的每个点。按几何和接触特征划分区域，优先扩展尚未探索且有可行依据的区域；抓点小幅移动仍归原策略微调，只有接触区域、接近通道或操作机制发生实质变化才可计为独立策略。
- 支撑面遮挡的底面不能直接穿透接近。对不易碎、不易撒且规则允许的物品，可以通过真实接触、重新夹取等多个阶段调整物体姿态，再完成抓取；这类阶段与中间放置必须记录，不能用瞬移代替。
- 两种停止模式都允许分段补充独立候选，先满足当前并行派发需要，根据新反馈继续拓展；跑满额度是总预算目标，不要求执行前写完全部候选或预设整套动作。尚未达到停止条件且候选不足时先补充，仍不足则如实说明缺口，请用户调整范围或单独安排微调、复测；不能重复命名凑数。每次新候选在执行前完成差异检查。

物理可行性检查应针对“当前物品、当前末端执行器、当前场景”，至少检查：

| 检查对象 | 判断要求 |
|---|---|
| 抓点与接触几何 | 是否存在可形成有效约束的接触区域；不要把暂时没找到抓点说成没有抓点 |
| 开合范围与指形 | 结合接触部位、手指形状和接近空间检查，不能只看物体外包围盒 |
| 质量、重心与力矩 | 核对机器人和末端执行器能力、姿态及动态载荷；尺寸小不代表负载可承受 |
| 可达性与碰撞 | 检查关节范围、工作空间、支撑面、遮挡和可行接近路径 |
| 接触与稳定性 | 检查材料、摩擦、可用夹持力和力矩限制；模型参数不足时标记未知 |
| 液体、散料与容器 | 区分直接抓取液体和抓取盛液容器；结合容器、密封和允许姿态判断 |
| 易碎、柔性或可变形物体 | 检查损伤约束、反馈能力及仿真模型是否足以验证；没有电子皮肤不自动等于不能抓取 |

家庭常用物品、体积不超过一立方米、或人类可以操作，都不能单独证明当前夹爪可抓。也不能据此轻易放弃：不可行结论必须有几何、能力限制或测量证据；未知与不可行分别记录。

用户导入常识文档时，先参考其逐物品建议，提取与本任务有关的操作约束并标明来源。它不能静默覆盖有效标准、物理事实或用户权限。遇到需要咨询的问题，先读取用户指定的专家或参考资料；若指具体服务或其他对话，仅在身份明确、工具可用且用户已授权发送消息时联系。没有入口时说明缺少什么，不捏造咨询结果，也不因非关键咨询阻塞其他可执行物品。

## 5. agent 闭环控制与多臂同步

**每批及每次续跑都核对监管是否有效。** X 直接取启动确认中用户选择的同时运行臂数，默认建议仍为 40 台，不另设第二个数量。按 X 台建立臂—物体—策略分配，在同批探索启动窗口内实际推进 X 个经实质动作去重的策略；不能以场景数量或改名候选代替真实并行与多样性。已明确数量不重复询问，未明确时保留启动前询问。读取持久配置、预算与最新现场反馈，持续核对每臂进展、续接/补位、实际并行、策略差异和监管新鲜度；跨天、对话恢复或程序重启不能仅靠聊天记忆恢复。具体见 [每批启动与持续监管](references/parallel-runtime-and-demo.md#每批启动与持续监管)。

**批量筛选与成功策略优化分阶段进行。** 整批按原预算或成功停止条件结束，完成在途动作处理及筛选所需复核/归档后，才可在明确的有限安排内单独优化已复核成功策略；不得筛选到一条成功就抽出提速复跑。暂停、技术中断或某臂完成不算整批结束。筛选期原有 FPS 维护、现场记录及必要复核继续执行。具体见 [批量结束后的成功策略单独优化](references/success-replay-and-acceleration.md)。

- 实际执行和演示前读取 [持续并行、后台控制与演示规则](references/parallel-runtime-and-demo.md)。核实后台观测、动作、复位、并行调度和数据保存链路，先确认能持续读到新数据并取得实际执行反馈。技能文件不提供这些接口；缺失时报告具体缺口，不能冒充完成操作。
- 接入控制接口时读取 [Trace 执行追踪规则](references/trace-and-replay.md)。每段动作关联所依据的观测、简短决策说明、实际指令和后续反馈；分别记录准备、发送、执行确认及结果，不能将发送成功当成执行成功。
- 循环执行：读取带时间戳的反馈 → 判断各臂状态 → 下发各臂短时动作 → 观察新结果。到位、超时、物体移动和复位完成后及时进入待决策并批量续接；结合实际进展判断有限延续；触碰使物体移动或旋转后，按 [定位与目标更新](references/parallel-runtime-and-demo.md#物体移动后的定位与目标更新) 依据新位姿换算抓点和通道，使失效旧目标退出执行，不沿用旧世界坐标，也不跨环境套用定位。动作、决策等待和有限恢复上限写入本轮配置，具体遵循 [检查点续接规则](references/parallel-runtime-and-demo.md#检查点后的动作续接)。
- 探索时可以使用关节控制器、IK、轨迹插值和执行脚本落实短段动作；不得预先固定整条抓取流程连续播放，再称为 agent 依据实时反馈探索。整批筛选结束后的独立成功策略优化，可使用从实测提炼的参考动作和状态条件进行有限反馈复跑，须标明模式、适用范围和新复核结果，不能冒充新策略探索或大模型每步重新决策。
- 同步表示多个独立机械臂环境在同一仿真时间段推进。可批量提交各臂不同的短动作，不要求创建同等数量的 AI 对话。不能逐臂跑完整段后报告多臂并行。
- 批量读取全体反馈、批量下发不同动作，各臂独立推进阶段，不设置不必要的全场等待屏障。单臂失败、完成或等待决策时，其余臂继续执行反馈有效、仍在授权时限内且未触发停止条件的动作；本地控制器承担高频执行与即时故障处理，不能无限续播或擅自决定整套抓取策略。
- 失败及时隔离，淘汰后沿用原预算完成必要复位、候选检查和机会预留，再及时补位。记录从策略结束到下一策略实际开始的延迟及原因，不能只把候选放入队列就报告补位完成。
- 明确展示各臂的运动、有效保持、测量、等待决策、复位或补位、已隔离或失败、完成状态。有效持握时静止属于工作，等待新决策不冒充测量或有效保持。
- 同一物品的同时探索臂执行不同的独立策略；相同策略的并行复测只能属于已明确的验证安排，不能报告为多个新探索方案。
- 各环境独立记录物品、控制输入和结果，避免相互串写状态。对同一执行接口只保留一个控制者。
- 观测过期、接口断开或反馈异常时停止依赖该反馈的新动作，并使用预先定义的暂停或受控保持。单臂问题可隔离时，其余臂继续。
- 若物理在 agent 思考期间暂停，这段墙钟时间不能计为持握时间。成功测量使用仿真时间及真实状态。
- 不把每几秒暂停整个场景作为默认交互方式。局部可隔离时其余臂继续；确因共享仿真限制或无法隔离的故障需要全场暂停时，记录原因和时长，并如实说明并行受限范围。
- 允许试次之间复位，但不能通过附着约束、瞬移或拼接复位前后的片段制造连续成功。
- 性能不足时报告已验证的并行能力和可选调整，不能静默减少臂数、串行代替并行，或仍然声称达到目标数量。

## 6. 计数、调整与整批完成

严格按 [策略与预算规则](references/strategy-and-budget.md) 分配预算，先预留机会再派发动作，防止并行超额。

- 等待指令、接近超时、重规划、路线淘汰与实际抓取失败分开统计；既不把停住视为抓取失败，也不因未接触就豁免实际空夹。按 [动作中断与失败分类](references/strategy-and-budget.md#动作中断与抓取失败分类) 核对证据及预算，已开始后淘汰的机会不退还。
- 一个已实际开始的策略机会最多承受 3 次实际抓取失败。微调不清零，明显无效可提前淘汰，淘汰后立即接续下一个合格候选。
- “有 80% 把握稍调就能成功”表达的是高把握修正要求。没有校准依据时不生成虚假概率；记录失败证据、拟改参数和预期改善。
- 失败原因清楚、接近成功且小幅修正有实测依据时，在原机会内继续调整；明显偏离目标、持续无效碰撞或没有可解释改进方向时尽早淘汰。不能用不断微调绕过三次失败限制。
- 策略第一次满足探索成功条件后结束该策略的探索机会；必要复测进入已明确的有限验证安排。重复成功不增加独立成功策略数。
- 按逐物品确认的停止模式推进：达到 K 个已复核的独立成功策略时按达标规则收尾；可用机会为零时停止新机会分配，但不据此截断已预留或正在执行的机会。已领取机会按原失败上限及停止条件完成，且在途/待复核结果处理完后，才按额度耗尽收尾并转向下一物品；选择跑满额度模式时，不因找到成功策略而提前退出。预算是上限，达到成功目标后无需用完。正常收尾仍须完成在途处理、已约定的必要验证与归档；不把单个物品结束写成整批完成，也不把额度耗尽但未达 K 写成目标达成。
- 达到 K 时，统一记录停止事件并停止该物品的新探索机会、新探索试次及自动补位。已在途动作在安全边界收尾，保存实际结果；尚未执行的预留释放，已实际开始的机会不退回，不把目标达成取消记作抓取失败。多臂收尾可能使最终成功数略超 K，按实际报告，不删掉多出的数据。其余物品和可独立推进的机械臂继续。
- 用户叫停、关键测量或记录失效、无法隔离的技术故障、环境失控时暂停受影响任务，保留剩余额度与恢复点；不能将中断称为整批完成。
- 同一技术故障不能无限重启重试。本轮应有有限的恢复次数或时间上限；超过后报告阻塞。修复后继续原批次，不重新赠送预算。

额度耗尽而目标未达成时，agent 必须复盘策略覆盖、控制、感知、环境和实现问题，不能只归咎于物品或建议再烧额度。

对于用户另设的整批 N 次机会，先核对这是整批额度还是单物品额度，再报告每个物品实际获得的机会。N 达到或超过 200 时，按用户要求进行重点复盘；整批 N 达到 200 不等于每物品都得到 200 次。N 小于 200 时，不能据此宣布该物品已无可行策略，可以提出有依据的追加建议，但不得自行追加。无论额度多少，只要没有证实物理不可行，agent 都必须承担未完成任务的排查与改进责任；这不等于可以未经证据宣称所有失败都只有一个原因。

## 7. 原始数据、三张表与结果口径

执行和归档前读取 [记录与归档规则](references/records-and-archive.md) 与 [Trace 执行追踪规则](references/trace-and-replay.md)。

需要管理物品模型版本、跨批次检索或关联管理界面时，读取 [模型与抓取数据登记](references/model-registry.md)。

用户补充的规则和策略按 [五级评估](references/user-contributions-and-review.md#五级评估) 记录 S/A/B/C/D、证据状态、适用范围、理由及优化版本；待评不自动归 D，文本推演不能授予依赖实跑复现的 S/A。评级不是抓取成功或标准通过，服务器评分不自动采纳为通用规则；保留原文、历史评估与真实失败。

- 执行时同步记录真实动作、观测和事件，登记并复核成功；整批筛选结束后再按独立优化安排提炼复用方案。保留失败、掉落、中间操作、复位和技术中断记录，不凭记忆补造数据。
- 长期维护一张《成功策略总表》和一张《失败策略总表》；每次训练会话结束另生成一张《时间-策略方案表》，只包含本次实际执行的方案。三个表使用同一套物品、策略和修订编号。
- 同一策略多次成功只增加验证次数。曾失败后微调成功的策略，仍保留此前失败证据，不从失败历史中删除。
- 分别报告独立策略数、实际执行次数、失败次数、验证次数和标准通过数。成功总表与失败总表可能包含同一策略，不能直接相加当作独立策略总数。
- 缺少证据标记为“待验证”或“数据不完整”，不能算通过。探索成功、重复验证成功、标准验收通过分别报告。
- Trace 串联物品、机械臂、策略、修订、试次、短动作、预算事件和验收证据。三张表保留可定位原始事件的追踪入口；技术故障、记录缺口和事后整理单独标记，不补造现场记录。
- 向用户明确显示“已执行，待复核”“验证完成—成功／失败”“未完成—中断／缺证据”及“整批验证完成”，具体含义遵循 [记录与归档规则](references/records-and-archive.md)。每条记录关联物品、策略、试次、阶段结果、原始证据、失败原因和剩余工作；整批验证完成不等于全部策略成功。

本阶段默认是反馈控制与数据采集，不默认使用强化学习奖励函数更新神经网络。接触力、离桌、持握、掉落和任务完成等指标用于反馈、筛选和验收；不能把仿真次数或成功轨迹数说成模型已经学会抓取。若另行开展神经网络训练，单独记录算法、数据、参数更新、验证和部署，是否采用模仿学习或强化学习另定。

## 8. 性能、演示与交付

涉及录像质量、帧率核实和原始视频保存时，读取 [画面与录像规则](references/visual-quality-and-recording.md)。

每次仿真训练运行期间，持续执行“性能采样 → 发现退化 → 定位瓶颈 → 在授权范围内优化 → 同条件复测 → 保留有效变更或回退”的监管循环。启动加载、静态稳定、机械臂运动和录制阶段分别建立基线；持续记录显示 FPS、帧时间与卡顿、仿真推进速度、物理步耗时、控制等待及整体吞吐，不能仅凭静态 FPS 宣称动态训练流畅。按本轮实际负载配置监测周期、目标和退化触发条件，缺少实测依据时不承诺固定帧率。

优先排查渲染负担、重复进程、数据读写、控制阻塞和资源瓶颈。任何影响物理步长、碰撞、接触、测量精度、采样或验收条件的变更，都要重新验证并记录环境版本；不能为了提高 FPS 破坏试验有效性。“长期关注”指持续运行规则，不自动创建用户未要求的后台任务或定时提醒。

持续监管的具体时机、采样与有限优化安排见 [画面与录像规则](references/visual-quality-and-recording.md)。优化无收益或引入问题时回退；同一故障采用本轮有限恢复上限，不能无限重启。监测缺失时标记未核实，不能声称已经持续监管。未经确认不减少并行臂数或牺牲关键画面；需要改动物理、驱动或系统环境时沿用对应权限和试验变更规则。

默认通过后台接口控制机械臂、读取状态、监测性能和记录数据。按 [前台控制必要性与控制权归还](references/parallel-runtime-and-demo.md#前台控制必要性与控制权归还) 判断每个操作段：只有必须使用界面或核对实际显示效果时才短暂接管，接管前明确目的与完成条件，核验完成后立即结束并确认归还，不等整个训练或排查结束。读写代码、分析日志、统计、思考和等待期间不持续占用鼠标键盘，不无必要地激活窗口或抢焦点；后台可完成的操作不用前台。

归还状态按工具状态或可观察结果记录为“已确认”“未确认”“失败”，停止点击不等于确认归还。无法确认或工具不支持独立释放时如实说明；用户要求收回时立即停止新的前台输入。前台结束后保留仍获授权的仿真、后台控制和监测任务。出现跳窗、闪烁、黑屏或用户操作受干扰时，记录时间与操作，停止无必要的前台重复操作，优先后台排查；未经验证不能称正常，也不能只凭 FPS 提升宣布优化完成。每段接管、操作、完成条件、结束、归还状态和异常写入 [Trace](references/trace-and-replay.md#前台操作与归还记录)。

保留当前物品、标准和历史数据，先核对已有实例，避免重复仿真进程。录像在测量有效的前提下兼顾高画质和流畅度，实测分辨率、帧率、掉帧与录制开销；不能用加速或补帧掩盖等待。

修复持续并行问题后，按 [持续并行、后台控制与演示规则](references/parallel-runtime-and-demo.md) 实际展示不同策略并行和失败后的补位，用 trace 对比仿真推进、实际耗时、全场等待及补位延迟。没有发生或没有验证的环节明确标为未验证，不能仅凭场景中有多台机械臂、代码已修改或文档已更新就称为持续并行已实现。

结束或中断时交付：逐物品预算与完成情况、策略多样性摘要、三张表位置、有效标准版本、原始证据索引、trace 索引与缺口、物理限制或未解决问题、性能与持续并行实测、用户可见结果状态及恢复入口。报告本次实际成果与限制，不把文档完成、离线分析或脚本启动成功当成抓取完成。

## 9. 成功数据本地打包与可选回传

用户需要集中回传成功抓取数据时，读取 [成功数据回传规则与模块接口](references/success-data-upload.md)。先按 [小范围回传授权说明](references/success-data-upload.md#小范围回传授权说明) 告知支持开发者更新的用途，由用户选择少量新增规则或成功策略并明确同意。原始材料保密，按授权提炼通用经验用于版本改进；公开原始内容或模型权重训练仍需对应的独立用途授权。仅对选定且获准的成功试次，保留原有动作、观测、参数、环境、标准、验收证据和 trace 要求；独立策略数、重复试次数、标准通过数及上传状态分别统计。

附带模块按第 2 版导出契约核对机械臂/夹爪品牌、型号、模型版本与资产哈希，以及配置和判据的文件引用，再本地打包、去重、持久排队，并在配置后执行有限上传。必需信息缺失时保留本地证据并列为待补全，不能猜填型号；臂编号不代替型号。默认关闭、无接收地址；安装技能不触发发送。每台用户电脑使用自己的目录、接收方配置和明确授权，凭据不写进技能包；配置或授权缺失时只保留本地数据。模块不负责自动采集 Isaac 数据，也不替代成功复核；运行程序须在归档与复核后接入，未接入不得声称已经自动回传。

后台打包与发送须和物理步进分离，失败保留本地原件和队列，不阻塞仿真、不无限重试、不静默漏掉未打包记录。未完成全部标准但已证实成功夹取的数据保留其真实验证范围；上传完成不能改变物理或标准结论。

用户规则/策略贡献和成功试次分区管理；贡献分享、成功数据回传及原始内容对其他用户公开分别保留用途授权；获准用于版本改进的通用提炼结果按小范围授权说明核对。现有上传模块只按成功数据契约工作，不提供贡献接口或自动评级；没有中台时本地归档并如实标记。贡献提交、待扫描回执和选定清单发送门禁等客户端适配仍须实现与验证，服务端界面与接口按各自交付证据确认，详见 [分区与反馈边界](references/user-contributions-and-review.md#分区、授权与浏览反馈)。

维护、存档、配置和队列目录由当前用户配置或从已有有效记录恢复；不预填个人路径，不创建字面占位目录。技能目录与运行数据目录分开。

## 10. 用户配置与版本维护

更新前核对实际加载版本及必要引用，检查与当前项目规则是否冲突，保留可恢复的旧版本；配置及运行数据不随技能文件覆盖。更新完成后核对入口和引用，记录实际使用的版本。

按 [复用原库规则](references/user-contributions-and-review.md#更新复用原库) 沿用库标识、配置、预算和历史。只有确认首次使用或用户明确新建隔离项目时才建库；原库不可访问时先恢复，不能静默新建空库。迁移先备份、增量处理并校验，保留回退入口。

按 [原创证据与版本身份](references/user-contributions-and-review.md#原创证据与版本身份) 核验发布来源及完整性。保留适用的署名、许可与修改记录；数据分享和更新技能分别处理，版本更新不自动扩大数据授权。读到贡献文本或服务器评分不自动改写已安装规则。
