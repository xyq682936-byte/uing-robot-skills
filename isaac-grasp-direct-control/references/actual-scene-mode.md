# 实际场景模式与失败后的针对性探索

本模式与探索模式、优化结果模式同级，用于用户调用已有成功策略，完成具体场景中的任务并核验其适用性。场景可以包含新姿态、障碍、遮挡、不同摆放和多步组合操作。模式名称不表示已经接入真实机器人：当前技能直接执行范围仍为获授权的 Isaac 仿真；真实设备执行另需具备对应接口、现场条件及授权，仿真结果不冒充真机结果。

## 入口与完整链条

默认链条为：**探索模式 → 成功且整批探索收尾 → 优化结果模式 → 新版本复核成功并保存 → 等待用户调用实际场景模式 → 按当前场景执行与验证**。实际场景成功则保存该场景的结果；失败则 **总结原策略及失败环节 → 回到探索模式，基于原策略针对性探索 → 在原失败场景重新验证成功 → 保存新分支与经验**。

优化完成不自动启动实际场景模式，也不因空闲、用户沉默或“已优化”标记自行选择场景开跑。用户要求使用具体场景时，沿用已明确的配置，只补齐缺失的任务、场景、源策略版本、验收范围、参与设备及有限执行/恢复安排。没有优化收益时保留原已验证策略，不能标优化成功；用户明确选择使用它时记录实际来源，不伪造优化经过。

针对性探索成功后，本链条收尾于复核与保存，不自动追加另一轮优化。后续确需优化仍适用整批结束、有限授权和完成去重规则。模式切换不取消已有停止条件；资源、预算或接口不足时保留状态与待办，不无限重试。

## 场景与任务验证

1. 记录场景及任务身份、物体与碰撞版本、设备/夹爪、有效标准和目标，比较源策略条件与当前条件：初始位姿、支撑、障碍/通道、可观测性、操作顺序、阶段前提和终态。未变化的条件也保留版本引用，不仅改场景名称。
2. 可以复用源策略的已验证动作和状态条件，并根据新反馈定位、避障和衔接；物体移动后及时更新目标，不能照搬旧世界坐标。超出原适用范围的部分标为待验证，旧成功不能替代新场景实跑。
3. 多步任务分别记录阶段条件和交接状态，并以同一次连续执行核验整体目标。夹起成功不等于搬运、避障、放置或整套组合成功；不能拼接独立成功试次充当全任务成功。局部诊断或必要复位与正式连续验收分开记录。
4. 单次运行、必要复测和故障恢复采用本轮明确的有限安排。实际场景运行不自动变成默认 40 臂、200 个探索机会；确需批量探索时再沿用有效的探索预算、用户确认的 X 和成功停止目标 K，缺项才询问。同一策略的场景复测不增加独立策略数量。

## 失败后的针对性探索

先保留原成功策略、完整失败证据和现场状态，区分定位/观测失效、碰撞表示失真、通道受阻、接触或承力不足、动作衔接/顺序、执行故障及证据不足。没有证据的原因记为假设，不先归咎于物体。技术故障按原有有限恢复安排处理，不能一律算实际抓取失败。

整理一份简短的失败摘要：源策略哪些步骤仍有效、失败发生在哪一步、场景发生了什么实质变化、下一步检验什么。保留有效抓取部位、接触关系或动作片段，围绕有依据的问题安排短段反馈控制；例如仍能夹稳而搬运被挡，应优先探索搬运路径或顺序，而非把所有抓取步骤推倒重来。局部修正不足时，可依据证据扩展探索范围。

进入探索后继续维持用户确认的 X 个实质不同策略、独立推进、补位和持续监管。沿用适用的剩余额度；没有额度或需要追加时按原规则确认，不能因切模式清零失败或自动增发机会。小幅修正属于原策略修订，有新的接触/承力机制或实质路线时才按 [策略差异与预算](strategy-and-budget.md) 判断新策略；所有候选检查历史成功、失败和当前队列，不能改名凑数。

针对性探索的目标与计数范围须绑定本次失败场景。旧批次已经达到的K及历史成功不能直接满足新场景目标；仅在新场景复测旧抓法成功，也不产生新独立策略。需要小幅修订旧策略时，沿用已确认的有限场景恢复/微调安排，不重开已结束的原机会，不占“新增独立策略”名额；未覆盖的安排才补问。真正不同的新策略按探索额度及适用K计数，场景恢复则按本轮完整任务成功条件判断。两类分别记录执行、失败与剩余上限，不以模式切换重置任一计数。

候选成功后，要回到原失败的场景条件及任务目标重新验证，确认所针对问题得到解决；组合任务须完成约定的全流程。只在无障碍环境再次夹起不能宣告障碍任务解决。新分支若仍声称覆盖原适用条件，补做必要的有限回归；未验证的范围保留待验证标签。

## 与重复复训的区别

**实际场景验证，以及依据该场景失败证据进行的针对性探索，不算重复复训。** 已优化完成标记不能阻止这两类工作；原完成标记仍然保留，不能清除后重新入队。旧场景成功、新场景失败和新分支成功可以同时存在。

区分三类目的：使用/验证既有策略；解决已记录的适用性或任务失败；在同一条件下再次压缩时间或重复优化已完成策略。前两类按实际场景或探索记录，后一类仍受优化去重约束。仅改场景名、日期、编号或无关参数不构成新问题；不能把重复提速包装成针对性探索。

## 记录与保存

沿用原库、原三张表及稳定策略编号，不新建第二套成绩库。每个场景任务记录模式与切换原因、场景/任务版本、源策略及优化完成记录、条件差异、失败阶段与证据、简短假设和改变、探索额度事件、父子分支、场景复核及完整任务结果。成功分支关联原策略，区分最新编辑版与最新验证通过版。

状态区分等待用户调用、执行中、待复核、场景验证成功、场景失败待针对性探索、探索中、恢复验证成功、暂停/额度耗尽/缺证据。成功只覆盖实际验证的场景和目标，不覆盖所有新场景。规则维护不等于模式调度、控制和界面已经实现。
