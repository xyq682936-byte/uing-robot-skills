# 抓取分阶段验证与完成状态规范

版本：2026-10-23。适用于已授权的 Isaac Lab / Isaac Sim 抓取探索与有限复测。它规定执行、记录和交付方式，不新增抓取合格阈值，不自动启动仿真。

## 1. 总流程与适用范围

按“夹取核实 → 已选性能测试 → 证据复核与归档”推进。已授权且条件齐全的后续步骤连续完成，无需用户逐步催促；异常时按既有恢复上限处理。

这个顺序按每条试次执行。单臂完成夹取核实后可进入其性能测试，其他机械臂继续各自阶段，不设置全场等待屏障。同一物品使用不同已登记策略；验证复测不冒充新策略。

测试矩阵必须在执行前记录每个物品、策略修订、试次数、必做阶段、条件适用阶段、停止条件和所需证据。“其他验证”仅指本轮已明确选用的项目；不得自动扩展到全部 NIST 章节、搬运、放置或新的物品。

每个数值条件记录来源：标准原文、仿真适配或项目自定。夹取高度、保持时间、容许运动、接触判定及加载设置按有效配置执行；缺少必要值时标为“待配置”，不能执行后按结果补定及格线。用户既有明确配置继续有效。

## 2. 阶段 A：夹取核实

先执行真实接近、接触、闭合和抬升，并记录物体、夹爪与支撑面的原生状态。观察物体由夹爪承载、离开支撑面，核对有效接触、物体相对夹爪运动、支撑力及异常碰撞。针对不同末端执行器使用相应接触条件，不把双指接触写成所有夹爪的通用要求。

采用本轮声明的夹取条件逐项核实；若要求保持，记录连续仿真时间内的稳定情况。不能用聊天等待时间、跨复位片段、强制附着、瞬移、穿透或外部支撑凑成有效持握。

只证明离桌时，结果写“离桌已确认”；同时完成约定保持等条件后，才写“夹取验证完成—成功”。不把进入加载阶段自动当成完成了未规定或未测量的稳定保持测试。

真实未夹起、意外掉落、严重弹出等按有效规则记录失败。该试次不满足性能测试前置条件时，后续阶段写“不适用—夹取前置条件未满足”，不得写成后续测试成功，也不记成额外一次实际测试。

## 3. 阶段 B：所选性能测试

仅让前置条件已满足的试次进入相应测试。进入时记录阶段边界、当前抓持状态、加载或运动目标及测量窗口。

采用 NIST SP 1227 草案第 5 节时，原文是圆柱试件抗滑测量：沿轴向增加拉力，记录力随时间变化，视觉确认明显滑动，重复并报告统计量。它没有统一合格线。使用日用品或不同夹持形式时说明适配范围，不称完整原文复现或官方认证。参考：https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.1227-draft.pdf

抗滑试验中，按程序逐渐加载后发生的滑动是预期测量终点；它不自动推翻阶段 A 的夹取成功，也不自动算一次探索失败。加载前掉落、非预期失控等另行记录，避免同一事件重复计数。

位移触发只产生待复核事件。确认滑动前最大拉力须关联力曲线和足以区分滑移、转动及可逆变形的视觉证据。加载轴偏离、接触支撑面、传感器失效、帧缺失等导致相关测量无效或不完整，不能从截断曲线提取一个峰值就宣布测量成功。

若达到已声明的加载上限仍未滑动，并且全过程条件有效，报告“在该上限内未观察到滑动”和有效的抗滑能力下界，不能称已测得最大抗滑力。有效下界可以作为声明范围内的完成结果；原计划若要求测到滑动最大值，则仍须注明该项未取得。

## 4. 阶段 C：证据复核与归档

逐条核对动作执行反馈、时间连续性、复位边界、接触与支撑、力与运动、终点事件及必要视觉证据。失败也要有依据；通信中断或证据缺失不能猜成抓取失败。

优先复用相同有效条件下已完整保存的原始证据。离线复核明确标为离线；重新启动原生物理执行另记新试次。旧数据只支持其实际测量过的条件，不能追认未测项目。记录状态重建画面须标“原生状态重建回放”，保留数据与帧映射，不冒充当时摄像画面；能否支持某项结论按有效测试方法核实。

需要视觉判读时，在试验前落实采集入口和保存方式，至少覆盖判断所需的完整事件窗口，并与原生时间戳对应。没有充分覆盖的截图不能自动作为滑动终点确认。使用过期画面、只展示精选成功片段均不能补足证据。

完成复核后更新同一套成功策略总表、失败策略总表、本次时间—策略方案表及证据索引，核对计数和链接，并同步用户指定存档目录。更正追加修订记录并保留原结论、依据与更正原因。

## 5. 每条试次必须怎样记录

| 记录组 | 必需内容 |
| --- | --- |
| 身份 | 批次、物品与资产版本、机械臂实例、机械臂及夹爪品牌/型号/模型版本/资产哈希、父策略、修订、机会、真实试次编号；复测关联来源试次和冻结设备配置 |
| 范围与判据 | 有效标准名称与版本、适配范围、配置和代码版本、该试次必做阶段、各条件的数值与来源 |
| 时间与连续性 | 阶段起止墙钟时间及其时区、仿真时间、物理帧号、复位序号；暂停不计入物理保持时间 |
| 夹取事实 | 物体及末端位置和姿态、关节状态、可用接触与支撑反馈、离桌和保持窗口、异常运动；不可测量写缺失 |
| 性能测量 | 实际加载、传感器读数、相对运动、轴向误差、峰值及提取区间、终点类别与适用限制 |
| 视觉证据 | 原始录像、连续图像或声明类型的回放路径、覆盖帧范围、与试次的对应关系、复核结论与判读者 |
| 动作与预算 | trace 入口、依据的观察、决策摘要、动作请求及实际起止、失败事件、修正、复位与预算变化 |
| 结算 | 每阶段执行状态、复核状态、结果、未完成原因、下一步、归档状态及证据链接 |

每次阶段结束、失败、复位和中断立即保存检查点；不能只在最后写一段总结。高频数据放原始轨迹，汇总表放可定位的路径与帧范围。具体 trace 字段沿用 trace-and-replay.md，不另造不兼容身份。

## 6. 用户看到的状态必须分开

每阶段分别保存 execution_state（未开始／执行中／已执行／中断／取消／不适用）、review_state（待复核／已复核／证据缺失／不适用）、result（成功／失败／有效测量／有效下界／无效测量／未测）及 evidence_refs。整条试次另存 archive_state、下一步和阻塞原因。标准评价单独记录；没有统一合格线时写“未评级”，不等于测量未完成或不合格。

| 用户标签 | 条件和含义 |
| --- | --- |
| 未开始／进行中 | 尚无最终执行结果，不能算跑完 |
| 已执行—待复核 | 动作已经结束，判定或证据尚未核实；不能算验证完成 |
| 验证完成—夹取成功／夹取失败 | 阶段 A 的适用条件和证据均已复核，结论可追溯；失败也能是完成的验证结果 |
| 测量完成—有效数值／有效下界 | 阶段 B 的声明程序和证据完整，报告测量范围；没有合格线时仍可完成测量并标未评级 |
| 未完成—技术中断／证据不足 | 需修复、补录或补跑，列出剩余事项 |
| 已结束—测量无效 | 已复核并查明无效原因；可计入已执行，不能计为有效测量或验证目标完成 |
| 不适用—前置条件未满足 | 依据原定测试矩阵跳过后续阶段；单列数量，不计为执行过该测试 |
| 已取消 | 用户取消的工作，保留原计划和取消依据；不能改称完成 |

颜色只作辅助，必须同时显示文字、原因和证据入口。最简用户表显示：物品｜策略及修订｜试次｜夹取阶段｜性能阶段｜证据复核｜归档｜下一步。

## 7. 进度与“全部跑完”的定义

至少同时显示以下数量，分别注明分母和单位：

- 执行进度：有实际执行终点的机会／计划机会；取消、未执行、技术中断分别列出。
- 夹取结论：成功、失败、仅确认离桌、待复核、未执行的试次数；失败后成功保留两次真实试次。
- 性能测试：符合前置条件的数量、实际执行次数、有效数值、有效下界、待复核、无效及中断次数。
- 归档进度：已复核并归档的记录／本轮需归档记录；原始证据缺失不能用文档存在代替。
- 独立策略数、修订数、机会数、实际试次数、复测次数分别统计；合格数量仅在存在明确有效判据时显示。

“执行进度 100%”仅表示机会执行已结束，不能把它作为验证总进度。必做项和条件适用项的分母来自执行前的测试矩阵；前置条件失败或用户取消须留下依据，不能事后删分母使成功率变高。

只有全部必做及适用阶段取得完整、经复核的结果，测试要求的重复与统计已完成，无待复核、缺证据或中断事项，且归档核对完成，才显示“整批验证完成”。失败可以包含在这一结论内；应同时报告成功与失败数量，不能写“全部成功”。未评级本身不阻止一个无合格线的测量任务完成。

如果恢复上限已到、条件不可实现或用户决定停止，显示“带缺项结束”或“已取消”，并列出未完成数量、具体限制和恢复入口；不能让界面永远显示进行中，也不能改称完整验证完成。该批所有记录均已归档不代表所有测试目标都已取得。

## 8. 补跑与预算

证据完整的阶段不重复消耗预算。缺项能由原始数据可靠复核的先复核；确需新的物理试验时，建立关联复测试次，保留原失败、中断与无效测量。

补跑使用已授权的有限验证安排，记录每条补跑次数、修复目标和退出条件。用户要求完成剩余验证时继续已有范围；不得自行重开耗尽机会、增加物品、无限调到成功或把整批再跑一遍。真正新增探索额度按 strategy-and-budget.md 确认。

同一技术故障遵循本轮已声明的恢复次数上限；超过后保留恢复点并交付缺项。夹取成功后按程序拉滑不消耗抓取失败次数；加载之外的实际失败、技术中断和复测次数分账。

## 9. 最终报告格式

开头直接给出：本轮状态；计划与实际执行数量；夹取成功与失败数量；有效性能测量与剩余问题；独立策略和复测数量；有效标准及适配范围；标准评价是否有适用合格线；归档位置。

报告“多少个成功”时必须写清统计单位和成功阶段，例如“夹取核实成功 X 次／Y 次实际试次，覆盖 Z 个独立策略”。不得用一句“成功 X 个”同时代表物品数、策略数、机会数、性能测量有效数或认证数。

规范、技能、配置和界面的更新各自记录实施范围。只有文档或技能更新时说明“规则已更新”，不能声称执行器门禁、状态面板或新物理验证已经完成。
