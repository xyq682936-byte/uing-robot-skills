# Trace 执行追踪与复核

接入控制接口、实际执行、恢复和验收时读取。Trace 用于回答：依据什么观测采取了什么动作，仿真实际发生了什么，预算怎样变化，结论由哪些数据支持。它不是神经网络训练，也不自动证明符合标准。

## 启用与文件

- 在本轮配置记录 trace 格式版本、存储位置、记录者和刷新方式。优先复用已有事件日志与原始轨迹，补足关联字段，不要求另建追踪服务或上传到外部平台。
- 建议会话目录使用 `trace/events.jsonl` 和 `trace/index.json`；允许等效格式及分片。索引记录文件、事件范围、已持久化位置、关闭分片的校验值、原始数据位置及缺口。哈希用于核对副本，不代表第三方认证。
- 实际运行前用已授权的接口检查事件能写入、读回并关联原始测量。仅安装技能、生成空文件或通过格式校验，不能报告运行时 trace 已接入。

记录探索/优化结果/实际场景模式、切换原因及源试次。探索只保存可审查的观察依据、简短假设、拟检验的动作与实际结果，不要求逐步内部思维；组合操作关联前后条件和阶段依赖。优化记录来源成功集合、全体相关成功臂数据索引、任务去重身份、领取/暂停/恢复、源与结果版本、新执行复核及最终完成标记；证据缺口或运行退出不能补造复训完成。

实际场景还关联用户调用、场景/任务及源策略版本、条件差异、失败阶段、保留/修改的步骤、针对性探索假设与证据、父子分支和完整场景复核。碰撞内存修正记录发现依据、用户选择、授权批次/范围及失效条件、逐次应用/回退、资产哈希、运行碰撞版本、前后有效物理参数与分组统计；旧授权不能替代实际加载证据。

## 事件关联与时间

格式版本从 `schema_version: 1` 开始。每个事件至少保存以下信息；不适用字段可为空并说明范围，不得编造值。

| 信息 | 字段或含义 |
|---|---|
| 会话和顺序 | `trace_id`、`event_id`、会话内单调递增的 `event_seq`、`event_type`、`batch_id`、`session_id` |
| 参与对象 | 涉及的 `actor_id`、`env_id`、`object_id`、`strategy_id`、`revision_id`、`trial_id`；机会单独编号时保留 `opportunity_id` |
| 动作关联 | `action_id`、`parent_event_ids`、`observation_ref`；实际指令与观察区间通过这些关联追溯 |
| 双时间基准 | 含时区的墙钟时间、会话内单调时钟；涉及物理事实时记录仿真时间、物理帧号及复位序号 |
| 有效版本 | `protocol_id`、`environment_id` 及可解析的配置、资产、控制程序和判定程序版本或摘要 |
| 事实与证据 | 事件内容、结果状态、`evidence_refs`；注明是现场实测、控制请求、估计还是事后关联 |

批量命令可对应多个机械臂，但要保存每个机械臂实际参数、状态及反馈，不能将全批成功状态复制给所有臂。同步性依据共同仿真时段核对，日志写入先后不能证明串行或并行。

## 每段控制必须可追溯

1. **观察**：引用带物理帧号和时间戳的原始状态，记录所依赖的物体、夹爪、关节、接触等实际可用测量及新鲜度。缺失量明确为空。
2. **决策摘要**：简短记录当前现象、采取的动作、拟调整参数、预期可观察变化及停止条件。说明继续微调、淘汰或切换的证据；不生成无依据的成功概率，也不要求逐字记录内部思考。
3. **指令准备和发送**：先持久化动作身份、关联观察、各臂目标、坐标系、单位、持续时间和适用限值，再发送。保留原始指令；低层控制器裁剪或变换后，另记实际接受的参数。
4. **确认和执行**：区分已准备、已发送、接口已接收、实际开始、完成、拒绝、超时及结果未知。执行起止对应物理帧范围；发送成功或接口应答不能替代原生执行反馈。
5. **结果**：关联新的观察、实际偏差、抓取或掉落事件、失败原因和下一步选择。连续多帧同一掉落只登记一次失败。未完成动作标记未完成，不能补成成功。

物体被触碰移动后的重规划事件，关联移动前后物体/部件位姿与时间戳、坐标系及环境身份、旧目标失效、取消/替换请求与实际确认、新目标和下一段实际开始。实测位姿与生成的目标分开保存；无法确认旧命令是否停止时标明未知，不能补成取消成功。

通信超时后先查动作状态，禁止不查证就重复下发。接口支持幂等时重用动作身份；不支持时标记执行状态未知，暂停受影响的新动作并核对原生状态。追加日志更正事件并关联原事件，不覆盖已发生事实。

## 前台操作与归还记录

每个短小的前台操作段使用独立的关联编号；与仿真会话、相关动作和异常事件关联。按 [前台控制必要性与控制权归还](parallel-runtime-and-demo.md#前台控制必要性与控制权归还) 记录以下信息，不用整次训练的起止时间代替单段前台操作的时间：

| 信息 | 记录要求 |
|---|---|
| 原因与范围 | 接管原因、为何需要界面或实际显示核验、具体操作目的及完成条件 |
| 开始 | 实际开始时间、相关工具/会话、可用的工具状态证据；未执行的请求不能当作实际接管 |
| 实际操作 | 已发生的点击、设置、视角调整或取证等操作及结果，关联工具调用或证据入口 |
| 完成条件 | 是否满足及核验依据；未知与未满足分开，不以“已发出操作”代替完成 |
| 结束与归还 | 前台操作结束时间、释放动作或工具状态、归还判定时间与证据；不知道真实结束时间时留空并注明，不能补造 |
| 归还状态 | “已确认”：有工具状态或可观察结果支持接管已结束；“未确认”：证据不足或工具无独立释放能力；“失败”：释放操作明确失败或仍有接管证据 |
| 异常与用户收回 | 窗口跳转、闪烁、黑屏、操作被打断的时间及对应操作；用户要求收回的时间、停止新输入及后续处理 |

操作段结束、任务完成、停止点击和后台仍在运行，均不能单独作为“已归还”的证据。尝试释放失败后若再次处理成功，追加更正事件关联原记录，不抹去失败过程；未确认状态应明确告知用户。记录不了的时间或状态保持未知，不能凭任务进度推断控制权。后台任务是否继续另行记录，不能以保留后台任务为由继续接管，也不能为释放桌面擅自结束后台任务。

## 预算与标准证据

- 机会预留、实际开始、失败、淘汰、成功、中断、恢复和复位分别记事件；预算变化包含变更前后数值、原因和唯一事件身份。恢复或重复导入按事件去重，不清零失败、不重复扣减额度。
- 成功目标的确认与调整、独立成功集合去重、达到 K 的停止触发、在途收尾、未执行预留释放及换物分别记录。区分因目标达成取消、真实失败、技术中断和额度耗尽；在途额外成功照常归档，不删除以凑 K。
- 有效标准落实记录关联：原文条款及版本 → 实现位置和实际运行值 → 传感器或加载响应 → 判定。未落实项明确列出，不把配置文件存在当作测量有效。
- 每个验收结论关联所用判定版本、原始数据区间、指标值与单位、阈值来源及逐项结果。探索成功、复测成功、标准通过、未测试和证据不足使用不同状态。没有官方合格线的指标记录测量结果，不自动生成“标准通过”。
- 持握和加载持续时间使用连续仿真时间。思考等待、暂停和复位前后片段不能累加。物理帧或关键测量缺失时，受影响的验收窗口不得算完整通过。

## 持续监管的证据

每批开跑前按 [快速规则复核](parallel-runtime-and-demo.md#每批开跑前快速规则复核) 留下真实查阅时间、技能来源路径与版本/哈希、相关引用、批次/配置身份及简短检查结果；关联缺项/冲突及其处理，不用旧批次的“已读”状态代替本次实际查阅。规则复核记录与运行监管、物理成功分别报告，不补造检查。

按 [每批启动与持续监管](parallel-runtime-and-demo.md#每批启动与持续监管) 记录启动/恢复核对、监管检查、检查点处置、过期、中断和恢复事件，关联规则/配置版本、用户确认的 X、监管者与控制实例、臂—物体—策略映射、有效观测及物理步。保留检查时间、反馈年龄、待续接/补位和实际处置结果，区分进程存活、反馈有效和决策推进；恢复不能用新事件填补此前监管缺口。配置数量、真实活动数量及差异原因可由同一时间窗口的原始事件核对，不能仅检查文件更新时间或心跳存在。

## 性能、异常与恢复

- 持续并行时记录每臂阶段与活动状态转换、检查点及其触发原因、进入待决策、新观察/重规划、下一段准备与发送、接收确认及实际开始；同时记录策略终结、隔离、复位、补位预留，以及全场暂停和恢复的原因与起止时间。续接和补位都要能分解等待环节，未完成事件保留起点、当前原因及证据缺口，不补造结束时间。状态关联实际观察，不能把有效保持与等待决策混为一类。指标计算和现场验证遵循 [持续并行、后台控制与演示规则](parallel-runtime-and-demo.md)。
- 高频原始数据保留在原有轨迹文件中，trace 引用其帧区间与字段，避免每帧重复写全部场景。验收所需采样不得为降低日志开销静默删减。
- 测量控制等待、仿真推进、记录写入及显示渲染的耗时，避免用 FPS 代替物理吞吐。配置记录可接受的观测时效和写入积压上限。
- 单一记录者或有序合并器避免多臂串写。关键派发与预算事件在执行前持久化，其他数据按配置及时刷新；关闭或暂停时核对落盘范围。
- 记录失效、磁盘不足、原始数据断流或积压超限时，停止受影响的新动作，采用预设暂停或受控保持，保留检查点。必要的故障处置不以日志恢复为前提；通过可用通道报告故障，恢复后标记缺口，不能补造现场测量。
- 新会话使用新的 trace 身份，并关联上次最后一个已核实事件和原批次预算。没有执行证据的准备记录不能据此算抓取失败或重新获得额度。

## 复核与交付

结束时核对动作与反馈关联、机械臂身份、仿真时间连续性、失败去重、预算守恒及验收原始证据；报告未知动作、缺失区间和不能判定的结果。三张表提供 trace 及事件入口，使每条结论能定位到实际试次。

涉及持续并行修复时，同时关联前后可比窗口的仿真推进时间、实际耗时、全场等待及补位延迟，并注明未结束事件。每条执行记录关联阶段结果、复核结果、失败原因与剩余工作；后台实时读写、前台截图或录像各自记录实际完成情况，不把录像存在当作控制接口已验证。

离线 trace 回看不执行动作；在仿真中重放属于新的实际执行，需要既有授权和已明确的验证安排。重放受环境和物理数值影响，不承诺逐位确定性，也不能增加独立策略数。整批筛选完成后的成功策略提炼、动作压缩与反馈复跑，另遵循 [成功策略单独优化](success-replay-and-acceleration.md)，不穿插到批量筛选中。保存原探索试次、源数据区间、提炼方案、优化修订、新复跑及独立复核之间的关联，实测量、指令与近似遥测分开并注明时效；新动作的成功必须来自新执行证据，不能继承旧轨迹的成功标签。

历史记录可以建立事后证据索引，但必须注明来源与缺失字段，不能据旧日志猜造当时决策、传感器读数或标准通过结论。
