# 成功抓取数据：本地打包与可选后台回传

在用户要求集中收集成功数据、准备上传或接入接收服务时读取本文件。此功能不改变原有策略预算、物理约束、成功判据或标准判定。

## 当前能力与启用条件

附带的 [本地模块](../scripts/success_upload.py) 使用 Python 3.10+ 标准库，可验证导出清单、打包、生成持久队列、去重、向配置的 HTTPS 接收端发送、核对回执和有限重试。

交付的 [配置模板](../assets/upload-config.example.json) 为 `enabled=false`、接收地址为空、授权未开启。安装技能、导入脚本、打包和查看状态都不会触发联网。没有接收服务时停留在本地队列；不创建后台常驻服务、系统启动项或自动任务。

**模块不是 Isaac 数据采集器或验收器。** 现有仿真程序须在真实采集和结果复核后，按下述接口导出数据，再调用模块。本次模块交付不代表已接入某个 Isaac 运行程序，也不代表任何抓取已经通过验收。结构校验只能检查清单和文件，不能证明文件中的物理结论正确或参数齐全。

在其他用户电脑上启用前，由该用户明确选择接收方、数据范围和回传授权；开发者安装技能的授权不替代其他用户同意。已有授权可复用，接收方或范围变化须重新确认。默认关闭；用户可通过停用配置或撤销凭据停止后续发送。已开始的请求可能已到达服务器，停用不能撤回已传数据。

## 小范围回传授权说明

只在使用者明确授权后上传。保留原有数据内容、成功复核、文件排除、分区、凭据、传输和重试规则；本节调整的是授权说明与选定范围，不把规则更新当作当前用户已经同意上传。

建议使用以下面向用户的询问，并展示本次实际清单：

> 为了支持开发者持续改进和更新，您是否愿意选择少量新增规则及成功策略回传？开发者将对您授权回传的原始材料保密，并将其蒸馏、提炼为改进后续版本的通用经验。您可以先查看或调整回传清单，只上传您明确同意的内容；不同意不影响本地使用。

1. “小范围”落实为用户选定的规则/策略及具体修订、成功试次或有限批次，不默认指全部历史库或以后自动产生的内容。用户可只选规则、只选成功策略或两类都选。确认前简要列出接收方、条目数量与身份、实际文件/数据类型及大小、用途和不包含的内容。成功策略可能包含既有规则要求的动作、设备参数、环境、标准、复核及trace，不能只说上传文字建议却发送完整轨迹包。
2. 提供“查看或调整清单”“同意本次选定内容”“暂不回传”等清晰选择，不默认勾选、不把沉默、安装、开始训练或提供想法视为同意。用户明确同意已有清单和用途时直接沿用，不再重复问；不同意继续本地使用，不降低训练功能或反复催促。
3. 记录授权时间、接收方、选定条目/修订及文件清单标识、允许用途和撤销状态。默认询问只覆盖本次选定内容及其必要的有界重试，不自动包含新条目、变更版本、其他接收方或新增用途。已有更广且仍有效的明确授权可以沿用，但不得把本次“小范围”同意升级为长期全量回传。撤销后停止后续发送；已在途或已接收数据的处置按既有规则说明。
4. 保密对象是原始规则、策略、附件、模型及执行记录等授权材料；接收方应限于获准人员和处理流程使用，原始材料默认不公开。这里的“蒸馏”指归纳、去标识和经验提炼，用于改进后续版本；可进入版本更新的通用结果须检查是否仍包含身份、私有模型、专有参数或可还原原始材料的信息，不能换个名字就公开原件。公开原始贡献或进行模型权重训练属于不同用途，继续按原规则另行授权；不能宣称本次已训练模型或完成蒸馏。
5. 保密和用途限制是接收方必须履行的要求，不是“绝对不会泄漏”的保证。接收方及相关处理边界尚不明确或无法遵守时，先保留本地并说明缺口，不用该文案掩盖实际权限/用途问题。贡献和成功试次仍走各自接口；未接入的功能不能用成功包冒充。
6. 发送前以有效授权清单核对拟发送内容。现有上传配置的通用scope标签不能代替逐条选择和用途记录；接入层需保证本次可发送队列只包含获准条目，旧队列中未获准的内容不得顺带发送。当前模块不提供选择界面或自动用途授权管理，这些适配列入开发需求；本次只更新规则，不开启上传或改动凭据。


## 与未来用户贡献中台的边界

本模块仍只处理成功抓取导出契约，不包含用户规则/策略提交、自动五级评级、检索界面或服务器迁移。按 [用户贡献规则](user-contributions-and-review.md) 单独记录这些建议、优化和评估；不得为了入库将未验证建议伪装为已复核成功。成功数据回传、贡献分享、原始内容公开可见及后续模型权重训练有各自用途授权；通用经验用于版本改进须在本次已说明并同意的提炼用途内，未接入时只本地保存。服务端交付与客户端适配分别核对。当前客户端仍需接入贡献提交、选定条目/修订发送门禁及待扫描回执。若接收方返回HTTP 202、stored=false和quarantined_pending_scan，不得记为正式入库或uploaded。现模块将此类回执记为rejected / invalid_receiver_ack，尚不提供完整待扫描状态管理；保留本地包，不能把stored改成true掩盖缺口。适配完成并验证前保持默认上传关闭，发布SKILL不等于开启回传。

升级复用已配置的数据根目录与上传队列，保留稳定记录/修订编号、包哈希和已有回执；不因换技能版本重复初始化空队列或重新上传所有历史数据。同一记录重复提交须幂等，同编号同修订内容冲突不能覆盖。需要队列/库结构迁移时先备份、核对兼容性并验证恢复，缺失迁移能力如实报告；这些运行约束不代表当前模块新增了通用迁移实现。

## 采集范围与结果口径

先用用户实际选定并授权的记录集合确定回传范围；可以是少量规则、少量成功策略/试次或已明确的有限批次，不自动扩大为全部历史成功。对该集合内**每条已复核成功的抓取试次**，保留本节原有完整证据要求；可以选择少量记录，但不能截取有利片段伪装完整成功。未选中的记录继续本地保存，不作为漏传项自动补发。重复试次保留自己的编号，但不增加独立策略数。相同试次的复核更正保留 `record_id`，递增 `record_revision`；不得覆盖旧证据。

| 内容 | 应保存的实际值及依据 |
|---|---|
| 身份与关系 | 物品、模型版本、批次、机械臂、独立策略、修订、机会、试次及阶段编号；微调父项和前序证据入口 |
| 物体与资产 | 几何/碰撞模型、尺寸、质量、重心、惯量、材料、摩擦、缩放、资产版本及哈希 |
| 机器人与夹爪 | 型号/模型版本、自由度、关节限制、开合范围、驱动、力/力矩限制、标定及坐标变换 |
| 控制与动作 | 真实下发命令、执行反馈、关节/末端轨迹、夹持参数、控制器参数、时间戳、决策 trace |
| 观测 | 物体姿态、关节状态、接触力/力矩等实际可用测量；明确单位、坐标系、采样率和传感器来源 |
| 环境 | Isaac Lab/Sim、物理引擎和驱动版本、物理步长、求解器、碰撞配置、重力、桌面、光照/相机、随机种子及扰动 |
| 标准与验收 | 标准名称/版本/来源、适用条款、仿真适配、项目参数与阈值来源、各阶段原始测量、复核结果与未完成项 |
| 复现信息 | 运行配置快照、代码版本/变更摘要、依赖版本、资产引用、原始数据索引；所需且允许分享的资产、标定和原始视频 |

“全部参数”指该试次的有效运行配置和与复现有关的数据，不是扫描整台电脑、上传全部环境变量或账号资料。外部资产依赖逐项列出；不能分享的模型或标准全文保留来源、版本、哈希及未上传原因。无测量值、未采集量、缺失录像和受限资产写入 `omissions`；不能编造默认值填空。缺少成功判定所必需的证据时不得进入已复核成功队列。

已证实成功夹取、但尚未完成全部标准测试的试次可以回传，须标记探索/复测成功，并保留标准的 `not_tested` 或 `incomplete` 状态。后续性能加载试验测到滑移不自动抹去前阶段抓取成功，按 [分阶段验证](staged-verification.md) 解释。不得把上传成功计为标准通过。

本功能不默认为独立失败数据建立外传任务。若成功策略经历过失败，保留本地完整历史；回传包内关联其版本和修订依据。确需加入失败片段或其他数据时，先核对已有授权范围。

## 导出接口

采集程序先完成归档，再生成一份**冻结、可分享的导出目录**及 JSON 清单。模块只读取清单逐项列出的文件，不递归搜集目录。原始本地存档仍按 [记录与归档](records-and-archive.md) 维护；导出目录不是唯一原件。

新导出使用 `schema_version=2`；连接配置与队列记录自身的版本仍为 1。清单必须包含下列字段。下例含需替换的身份与哈希占位文本，仅说明结构，不能直接打包，不是实测或默认物理参数：

```json
{
  "schema_version": 2,
  "record_id": "object-A-trial-001",
  "record_revision": "1",
  "object_id": "object-A",
  "batch_id": "batch-001",
  "strategy_id": "side-grasp-A",
  "strategy_revision": "2",
  "trial_id": "trial-001",
  "arm_id": "arm-07",
  "verification": {
    "review_state": "reviewed",
    "grasp_success": true,
    "scope": "exploration",
    "reviewer": "reviewer-id",
    "reviewed_at": "2026-10-22T12:00:00Z",
    "criteria_ref": "config/acceptance.json"
  },
  "object": {"effective_parameters_ref": "config/object.json"},
  "robot": {
    "manufacturer": "导出时填实际机械臂品牌或自研机构",
    "model": "导出时填实际机械臂型号",
    "model_version": "导出时填实际仿真模型版本",
    "asset_sha256": "替换为实际资产或完整资产依赖清单的64位SHA256",
    "gripper": {
      "manufacturer": "导出时填实际夹爪品牌或自研机构",
      "model": "导出时填实际夹爪型号",
      "model_version": "导出时填实际夹爪模型版本",
      "asset_sha256": "替换为实际资产或完整资产依赖清单的64位SHA256"
    },
    "effective_parameters_ref": "config/robot.json"
  },
  "control": {"effective_parameters_ref": "config/control.json"},
  "environment": {"effective_parameters_ref": "config/environment.json"},
  "standard": {
    "reference": "本轮所选标准或项目条件的名称与来源",
    "version": "实际采用的版本",
    "applicable_clauses": ["实际适用条款"],
    "adaptations": [],
    "threshold_sources": ["config/acceptance.json"],
    "status": "not_tested"
  },
  "provenance": {
    "code_revision": "实际运行版本",
    "units_and_frames_ref": "config/environment.json"
  },
  "omissions": [{"field": "video", "reason": "本试次未录制"}],
  "files": [
    {"path": "actions.jsonl", "role": "actions"},
    {"path": "observations.jsonl", "role": "observations"},
    {"path": "review.json", "role": "verification"},
    {"path": "trace.jsonl", "role": "trace"},
    {"path": "config/acceptance.json", "role": "configuration"},
    {"path": "config/object.json", "role": "configuration"},
    {"path": "config/robot.json", "role": "configuration"},
    {"path": "config/control.json", "role": "configuration"},
    {"path": "config/environment.json", "role": "configuration"}
  ]
}
```

- `scope` 为 `exploration`、`repeatability` 或 `standard`。`standard` 范围的成功要求 `standard.status=passed`；其他范围允许标准未完成。
- `standard.status` 为 `passed`、`failed`、`not_tested`、`incomplete`、`not_applicable` 或 `unrated`。无合格线的有效测量写 `unrated`，可随已复核的探索/复测夹取成功记录打包；不能冒充 `scope=standard` 的标准通过。`passed` 必须同时列出适用条款，真实符合程度仍由证据复核保证。
- 至少提供 `actions`、`observations`、`verification`、`trace`、`configuration` 五类非空文件。另支持 `asset`、`media`、`standard`、`calibration`。使用相对路径、正斜杠；不允许路径穿越、绝对路径、目录联接或符号链接。
- 机械臂与夹爪分别必填 `manufacturer`、`model`、`model_version`、`asset_sha256`；`arm_id` 只表示实例编号。自研设备写真实自研机构、型号/唯一设计标识及版本，不能猜填商用型号。哈希应来自实际资产；多文件资产可用已保存的完整依赖清单哈希，说明计算对象，不能拿根文件哈希冒充全部依赖。缺项保留本地原始成功证据并标待补全，不进入可发送队列，不由 `omissions` 豁免这些必填项。
- `object`、`robot`、`control`、`environment` 的 `effective_parameters_ref`、`verification.criteria_ref`、`provenance.units_and_frames_ref` 及 `standard.threshold_sources` 必须精确指向文件清单内的 `configuration` 文件。阈值来源至少包含实际夹取判据配置；`reference`、`version`、`code_revision` 不能空，条款、适配和阈值来源须为列表，复核及授权时间须带时区。
- 被引用的配置须导出为 UTF-8 JSON 非空对象，每份及清单大小不超过 4 MiB。更大的资产和轨迹作为独立列明文件保存，用小型配置快照关联，不把原始轨迹塞进元数据。模块拦截这些 JSON 中明显的凭据字段、绝对本地路径与非有限数值；其他原始文件仍由导出方核查可分享性。
- 包内 `manifest.json` 的 `data_root` 固定为 `data`，`files[].path` 为实际包内路径 `data/...`；参数和判据等引用仍相对于该数据根。接收端按 `data_root + "/" + 引用` 查找，不能把包根当作配置引用根。打包后及发送前核查引用、大小和哈希，发送前重新检查启用与授权。
- 导出方仍负责核对实际参数、关节顺序、单位、坐标、时序、依赖及现场真实性；模块只核验上述明确结构和文件关联，不解析任意 Isaac 日志/资产的物理含义，也不能证明已采齐全部参数。新增字段可以保留，结构检查通过不等于物理结论或数据完整性已获得独立验证。
- 清单不能包含密码、令牌、私钥或绝对个人路径。模块会拦截明显的凭据字段和文件名，但不具备通用脱敏能力；上传前导出方仍须检查数据内容。凭据仅从本机指定环境变量读取，不能写进公开技能包。

## 本地使用与接入位置

以下是通用命令模板，路径由使用者配置；占位文本不能作为真实目录创建。模块本身不需要安装第三方依赖。

```text
python "<技能目录>/scripts/success_upload.py" pack --export-root "<冻结导出目录>" --manifest "<导出清单.json>" --outbox "<本地回传队列>"
python "<技能目录>/scripts/success_upload.py" status --outbox "<本地回传队列>"
python "<技能目录>/scripts/success_upload.py" send --config "<用户本地配置.json>" --outbox "<本地回传队列>" --limit 5
python "<技能目录>/scripts/success_upload.py" retry --outbox "<本地回传队列>" --package-id "<需人工重试的数据包哈希>"
```

1. 将配置模板复制到用户自己的配置目录，默认保持关闭。数据队列放在用户指定的存档根目录内，不能写入分发用 SKILL 文件夹。
2. 运行程序在“试次完成→证据归档→复核成功”之后，交给独立的本地归档/上传工作进程调用 `pack`。不能在物理步进线程中压缩或等待网络；本模块不自动改写既有仿真程序。
3. 导出者逐条登记打包结果。缺字段、缺文件、锁占用或磁盘错误必须保留导出清单并报告待处理项，不能静默遗漏成功试次。对比本次选定且已授权的成功试次清单和队列，检查遗漏；未授权/未选中的本地试次不进入补发，模块不会发现尚未导出的试次。
4. 有接收服务并完成用户配置后，设置准确的 HTTPS 地址、相同的授权目的地址、授权时间及 `enabled=true`，在进程环境中设置 `token_env` 指定的凭据。密钥不在聊天或公开文件中传递。
5. 已授权的现有运行器可在归档后启动一次有限 `send`，与仿真解耦；Windows 后台进程使用隐藏窗口。定时任务、常驻服务及开机启动另行按用户需要配置，不能只因安装 SKILL 自动启用。

旧版迁移：保留第 1 版原清单、数据包和历史回执。新打包不再接受第 1 版；已排队旧包若不满足当前契约，在发送前转为 `needs_review`，不发送也不增加网络尝试数。已上传的历史记录不撤销、不自动补写型号。根据原始证据补全后，用原 `record_id` 和递增 `record_revision` 另建导出及新包，保留旧版关联；不能只改版本号或直接修改包内文件伪装迁移完成。

队列结构是 `packages/<sha256>.zip` 和 `jobs/<sha256>.json`。包内保存 `manifest.json` 与 `data/` 文件，每个文件均记录大小和 SHA-256；数据包另有整体哈希。相同内容重复打包不会创建新任务或清空上传记录。导出内容或复核版本改变会生成新包，接收端须按记录编号和修订维护版本关系。不同 Python/压缩库版本可能生成不同包字节，服务端不能只依赖包哈希判定“独立策略”。

不自动删除原始数据、队列或已上传包。磁盘空间由本地使用者管理，清理前保留必要证据和可恢复副本。

## 状态、有限重试与停止

| 队列状态 | 含义 |
|---|---|
| `queued` | 本地打包完成，尚未确认接收 |
| `retry_wait` | 等待下一次调用重试；前次超时也可能已到达服务器，必须使用同一幂等键 |
| `uploaded` | 接收端返回与包哈希一致的保存确认，保留回执和时间；不意味着抓取或标准再次通过 |
| `auth_blocked` | 凭据被拒绝，修复后显式重试 |
| `rejected` | 协议、回执或请求被拒绝，先排查再显式重试 |
| `corrupt` | 本地包缺失、不可读或哈希不符，不发送；从已核验的源恢复后另行处理 |
| `exhausted` | 本轮自动重试额度耗尽，保留任务，等待人工处理 |
| `needs_review` | 旧版、必需信息缺失、包内引用或证据不一致；保留包，不发送，回到原始导出核实并另建修订 |
| `invalid` | 检查时发现队列记录损坏或结构不合法；是诊断状态，原文件不覆盖，明确报告并继续处理独立有效记录 |

默认每个包最多 3 次发送尝试；每次调用对每个可执行包只发一次，最多处理 `--limit` 个可处理包。损坏队列记录单独报告且不占此上限，避免持续阻断有效记录。网络异常、408/425/429/5xx 进入有限指数退避，不原地无限等待或循环重启。401/403、其他拒绝及无效回执停止本次后续发送。没有未来调用时，等待队列不会自己醒来。

`retry` 只将指定的拒绝/凭据阻塞/额度耗尽任务重新排队，不立即联网；累计次数和历史保留。已经尝试过的包绑定原接收地址，不能通过更改配置静默发给另一方。新接收方迁移应由用户明确授权并安排单独队列；不要篡改旧回执。

进程退出后队列保留。操作系统锁防止同一队列多进程同时发送，进程崩溃后释放；发送前持久记录尝试并保留幂等键，不能承诺跨进程和网络故障“恰好一次”，服务端也必须去重。每个新请求前重新读取启用和授权配置；撤销不取消已经在途的请求。

## 接收端协议：未来配置时对接

客户端使用系统信任的 TLS 证书校验，流式 `POST` ZIP 到配置地址，不自动跟随重定向。不接受 HTTP、URL 内凭据或查询参数令牌。

请求头包括 `Authorization: Bearer <本机凭据>`、`Content-Type: application/zip`、`Content-Length`、`Idempotency-Key: <包SHA-256>` 和 `X-Content-SHA256: <同一哈希>`。接收端应验证权限、大小及哈希，安全保存，按用户/租户和幂等键去重，并核查文件清单与记录版本；安全解包需由服务端自己实现。

只有完成持久保存后才返回 2xx 和以下 JSON；HTTP 200、页面文字或“已排队”均不能替代保存回执：

```json
{"stored": true, "package_id": "<包SHA-256>", "sha256": "<包SHA-256>"}
```

重复收到同一包应返回同一确认。若返回体过大、不是 JSON 或哈希不匹配，客户端不会标记上传完成。客户端只保存必要的回执字段，不把服务端原始响应或密钥写入日志。

源码仓库附带 `tests/test_success_upload.py` 回归测试。在源码仓库根目录运行 `python -B -m unittest discover -s tests -v`，只使用临时合成数据、模拟传输和本机回环测试，不控制 Isaac，也不发送用户数据。测试覆盖结构、身份与引用、旧版隔离、队列异常、授权、重试、去重、哈希及回执；通过不代表真实服务器或仿真采集已接入。
