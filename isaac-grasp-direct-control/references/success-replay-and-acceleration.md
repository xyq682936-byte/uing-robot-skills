# 优化结果模式：批量探索结束后的成功策略复训优化

用户要求整理已完成探索的成功策略、压缩耗时或提速复跑，或者按已允许的空闲优化规则选取成功策略时，读取本文件。“复训优化”指实测方案提炼、复现及有限优化，不默认指神经网络参数训练。这里只规定工作流程，不附带通用轨迹提炼器、复跑控制器或性能优化服务，不因文档更新启动仿真。

## 阶段入口与适用范围

必须先完成本批策略筛选，再对其中已复核成功的策略另行优化。完成是指按本批约定的物品范围、预算或成功停止条件收尾，在途动作及筛选所需复核/归档已处理；暂停、技术中断、只完成某一臂或某一策略不等于整批筛选结束。

批量筛选尚在进行时，仍由 agent 根据现场新反馈分段探索，多个机械臂尝试不同策略并同步留存数据；可以登记成功和失败、执行原本必需的有限复核，但不能抽出先成功的策略，穿插本文件的轨迹提炼、动作压缩或提速复跑。不得用旧成功轨迹替代未成功的新策略探索，也不能为开启优化提前缩短原筛选任务。筛选阶段的既有 FPS 维护、故障处理和数据记录职责继续有效。

进入独立优化阶段时，记录已完成筛选批次、成功策略及具体修订、成功证据、适用物体/设备/环境/标准、优化目标、允许改变的范围、验证次数、配置尝试/恢复上限和停止条件。用户已允许的空闲优化规则或当次批准明确覆盖则沿用；执行范围或有限预算尚不明确时先补齐，不自行追加无限复跑。失败、未完成和证据不足的候选不混入成功策略优化集合；它们需要时另按探索或诊断安排处理。

工作顺序是：**完成批量筛选 → 核定成功集合 → 提炼实测方案 → 基线复现 → 独立任务内有限优化与反馈复跑 → 重新复核、完成标记与归档**。它不改变原有标准复测及 K 计数所需的验证安排，不代表必须等完整认证通过才允许整理已核实的有限抓取结果。

## 空闲批量优化与完成去重

1. 可按用户已允许的空闲优化规则，或用户当次批准的优化任务，大批量选择成功策略；两种入口分别记录来源。已明确的空闲许可可以持久沿用，不要求每次再批准。开跑前仍明确候选库/范围、资源与并行数、有限总时长/试次数、逐策略配置及确认上限、停止与恢复条件。仅修改本规则不启动仿真、常驻服务或定时任务；自动排程与接口实现另列开发需求。
2. “空闲”依据可用资源、用户优先任务及实际控制实例判断，不能仅凭用户没有发消息或 CPU 占用低决定。探索批次尚未完成不得穿插本模式；不抢占已有控制者、前台或用户任务。已批准的优化任务可在其授权资源范围内执行，不要求假称空闲。资源被收回、用户开始优先任务或达到停止条件时，在可控边界暂停并保存检查点；复用同一任务恢复，不重新开一轮。
3. 入队前核对成功证据、源探索批次完成状态和全部相关机械臂的成功数据，逐父策略及适用条件分组；不能只取最佳一臂而漏掉其他已确认成功策略。数据范围覆盖实际记录的状态、指令、接触、参数、环境、时间及证据，缺项说明。每次真实执行保持独立身份，不拼接不同臂片段制造一条连续成功。数据不兼容先分组，不强行混合。
4. 去重同时查询待处理、运行中、暂停、失败/待核查及已完成任务。使用稳定库标识、父策略及源成功版本、物体/设备/有效环境和标准适用范围构成任务身份，并核对实际动作等价关系；不以日期、文件名、任务号、臂编号或优化器版本作为重新训练的理由。源版本和产出的优化版本都关联同一完成记录，防止把优化产物重新当未优化输入。并行领取须有唯一执行者和可恢复记录，不让两个工作者重复复训。
5. 状态至少区分：未复训、排队、复训中、暂停、复训完成且有有效优化、复训完成但无有效改进、失败/证据不足、适用性待复核。完成记录包含完成时间、源/结果版本、适用范围、新执行和复核证据、时间收益及输出位置；文件夹存在或程序退出不能作为完成依据。完成但无改进保留原已验证方案，并明确本轮已结束，不为了追求更快反复自动复训。
6. **已复训完成的策略不再进入自动或普通批量复训。** 每次启动、恢复、导入和领取前重查完成标记；换日期、改名、复制到新目录、重启或换 agent 不清除标记。一次有界优化任务内部的基线复现、有限修改与冻结结果确认属于同一任务；完成后不再重复启动。必要的运行使用或用户明确要求的独立验证与复训分开计数，不能借验证名义再次开展优化。
7. 暂停只恢复未完成部分；失败和证据不足不能标完成，也不能反复自动新建任务。只在原任务剩余的有限恢复安排内处理，耗尽后保留状态等待明确处理。设备、资产、标准或任务条件实质变化时，保留原完成标记并标记适用性待复核；需要新的验证/探索安排时另行明确范围，不能借无关字段变化规避已复训跳过规则。用户明确要求重新优化某已完成策略时记录例外原因及新的有限授权，保留旧结果。

## 优化结果与操作记忆保存

在用户既有库的 `成功库/优化结果/` 下按稳定物体、父策略和优化任务保存，复用同一目录结构；这是原库内的独立文件夹，不另建一套正式库。每个任务保留源成功证据索引、全体相关成功臂数据清单、参考/优化方案、有效条件、基线复现与新验证、等待和动作分项耗时、失败/无改进、完成状态及版本关系。尚未通过新复核的候选留在任务工作记录中，不能作为已优化成功方案供检索。

只有重新执行且复核成功、有明确有效改进的版本才标“优化后成功”；完成但无改进时保留源已验证版本。该文件夹的完成状态作为同一优化账本的一部分，与原成功总表、失败总表、本次表及模型登记关联，避免多个相互冲突的完成标记；更新幂等，历史不覆盖、不重复累计。

结果用于后训练成功策略保存、未来控制对象操作时的策略建议及可检索的经验记忆，也供其他 agent 在授权范围内参考。标注适用前提、动作阶段、反馈条件、失败边界及组合接口；实际使用仍依当前反馈决定。组合操作及现实执行另需验证，保存与复训本身不代表模型权重训练、通用能力形成或真机部署完成。

## 优化完成后的实际场景入口

优化成功并保存后，等待用户调用 [实际场景模式](actual-scene-mode.md)，不因空闲许可自行运行新场景。实际场景验证及其失败后基于原策略的针对性探索不算重复复训，原完成标记不应阻止这两类工作，但必须保留。记录条件差异、失败阶段及新分支；只改名称、日期或无关条件，不能借新场景再次优化已完成策略。针对性探索成功后先复核、保存；后续优化仍须符合独立入口、整批收尾及完成去重条件。

## 现场记录与实测提炼

- 原始记录在探索/复跑现场同步保存。“反向整理”指事后提炼已存在的数据，不是凭文字回忆补造轨迹、接触或判断。
- 关联物体与碰撞版本、机器人/夹爪身份、初始状态、关节目标与实测、夹爪开合及力度模式、物体与末端位姿、接触和支撑力、阶段转换、碰撞/滑移/失败，以及仿真时间和实际时间。用 `action_id`、`trial_id`、物理步号及复位身份串联观测、简短决策摘要、指令和执行反馈，沿用 [Trace 规则](trace-and-replay.md)。
- 实测、指令和近似遥测分开，记录单位、坐标系、更新周期、样本时间与最大年龄。驱动 effort 或控制指令不能直接当作实测关节力矩；缺失或陈旧的关键测量不得用于补造验收窗口。
- 从已复核成功的实际轨迹和状态变化提取物体局部坐标下的抓点/方向、关键姿态、接触/承力关系、阶段顺序、进入/退出条件及保护条件。关节参考关联起始机器人状态和环境，不可脱离适用范围直接复用。
- 产物为“可调整时序的参考动作＋状态条件”，分别标记必要物理动作、有效持握/测量、纯等待及原失败恢复片段。只抄曾发送的目标不能证明它被执行；数据不完整、原动作偏离原因不明时先补核验，不能标已验证方案。

## 独立优化任务中的提速

1. 先测分项开销，再减少无物理作用的等待：不必要的对话往返、跨臂屏障、重复提交未变目标、重复图像读回、数据转换和静态重复渲染。允许后台本地控制器在既定参考动作、状态条件及保护范围内执行，agent 负责优化、异常决策与有限修正；不能把自动复跑描述为大模型每个控制步重新规划。
2. 已获授权的复跑臂各自按反馈推进，不等待最慢臂逐阶段完成。复位、暂停和批次收尾仍按实际耦合限制处理，记录确需共享等待的理由。接触建立、物体稳定、有效持握和标准测量时间不能归为无效等待删除；思考或暂停的墙钟时间不能计入仿真持握。
3. 动作速度按阶段调整。无接触段只在既有速度、加速度、驱动、关节限制及跟随误差范围内压缩；近接触、闭合、承力和抬升依赖实时状态，不能整段乘倍速后跳过检查。压缩时序或改变路径均生成待验证修订。
4. 删除历史绕行前确认它是否承担避障、重新定位或重抓功能；有必要作用的阶段保留。触发保护时局部隔离、停止依赖旧状态的新动作并按条件回退/重规划，其余臂可独立继续。回退也受当前反馈和原限值约束，不能把旧成功当作新捷径有效的证据。
5. 物体移动/转动后，使失效旧目标退出执行，按当前物体位姿重算目标和通道并检查适配；超过已配置的修正幅度、次数或时间范围时停止该臂复跑并重新规划。遵守 [定位更新](parallel-runtime-and-demo.md#物体移动后的定位与目标更新)；夹住后的滑移不能被反复更新成新理想参考来掩盖失稳。

## 物理条件与测量保持有效

不靠改变质量、摩擦、碰撞模型、夹爪能力或放宽判据换取速度。记录并核查原始与优化方案的有效配置、初始条件和版本；物理后端、控制或测量链路、采样方式发生变化时，明确变更、授权和适用范围，完成必要等价性检查及新实跑复核。数值一致性须覆盖本次所用量、条件与容差，不能用单次 API 返回相同证明所有物理行为等价。

可省略的动作终点或阶段，必须原本不属于当前任务和有效标准要求。若省略更高可选抬升终点，应记录终止触发条件、最大与终态抬升、实际持握和未执行步骤；不得声称完成了原末端目标或完整标准流程。标准所需高度、路径、载荷、时长和后续动作均不能删减。总提速要区分控制/调度开销减少、动作时序压缩与动作范围缩减，范围不同不能全部宣传为同一完整动作的计算加速。

## 性能与录像证据

按 [性能与录像规则](visual-quality-and-recording.md) 同时记录动作墙钟耗时、仿真推进、显示 FPS、实际新图像采集 FPS、最长画面间隔和控制等待。启动、预检、复位、动作和退出分别计时；不能把动作段时间当整次进程耗时，也不以 CPU/GPU 总占用未满否定关键串行瓶颈。

图像复用、异步编码、减少重复转换、进程调度和物理后端等候选设置，均按现有权限、同条件可比窗口实测收益；明确更高 FPS 与更短动作时间的取舍，保留所需视角及关键过程证据。无收益、黑闪/空白、画质不可辨或观测过期的设置回退，未观察的问题标未核实。具体核心选择、采样频率、分辨率、并行数量与目标秒数不成为其他机器的默认值。

保留原速录像及时间映射。为保持原始墙钟时长而重复编码源帧时如实披露实际新帧率、重复帧和最大间隔；封装 30/60 FPS 不是实时采集 FPS。不得通过视频加速、插帧、删停顿或离线改时间戳伪装控制提速，视频也不能替代物理复核。

## 重新验证、计数与采用

- 最终修订必须重新在仿真内执行，以与控制器完成标记分离的原生状态/接触测量及有效判据复核。只改程序、剪轨迹或离线重算旧成功不能证明新修订可执行。区分到位、离桌、连续持握、抓取成功与完整标准通过，沿用 [分阶段验证](staged-verification.md)。
- 配置尝试、确认复跑和故障恢复均有既定有限安排；成功后按停止条件收尾，无效或回退不抹除失败。修改中的优化轮与冻结最终版本的确认轮分开，不能把不同修订凑成同配置复现次数。
- 相同初始条件复现只证明该范围。随机姿态、其他物体、更多机械臂、不同后端或完整标准仍需相应验证，不外推通用性能或保证未来成功，也不表示发生神经网络参数训练。
- 同一成功策略的提炼/提速修订与复跑保留父策略身份，复测只增加验证记录；不增加独立成功策略数，不擅自扣探索预算。若修改实际构成新的接触/承力机制或实质独立路线，按 [策略差异与预算](strategy-and-budget.md) 重新分类和安排，不能借“优化”规避探索额度。每轮如实记录真实失败、保护中断和技术预检失败，不混算。
- 保存“原探索试次 → 提炼方案 → 优化修订 → 新复跑试次 → 独立复核”的关系、提炼方法版本、源证据区间、配置/资产哈希、原始和优化后各阶段时间、改变/保留条件、失败回退、trace 和原速录像。沿用原库及成功总表、失败总表和本次时间—策略表；不另建一套成绩库。
- 区分最新编辑版本与最新验证通过版本，更新可恢复的已验证入口而不覆盖历史。后续仅在明确授权、环境兼容和当前反馈有效时复用；不匹配先核验。单批次案例参数不写入通用默认值，私有案例与完整数据不随开源技能发布。
