# 策略、预算与状态规则

在生成候选、开始执行、恢复中断或追加额度前读取本文件。

## 策略身份与差异检查

为每个物品建立长期稳定的 `object_id`。重命名、复制资产和换目录不自动生成新物品。资产几何、材料或机器人能力变化时另记版本，以便解释适用范围。

用以下内容形成策略描述及可比较特征：抓取区域、物体坐标系下的接近方向或通道、夹持方式、姿态重排方式、关键动作阶段、反馈调整原则。相同策略使用稳定的 `strategy_id`，小幅参数修改使用 `revision_id`。

仅改变坐标数值、角度、速度或夹力，通常是微调；若变化实际改变接近通道、接触区域或操作机制，应记录实质差异后再判为独立策略。不能只依赖参数差值或文本相似度。

候选覆盖按下节的结构、两指接触关系与通道检查；动作差异判定、机会计数和停止条件同时适用。

本轮候选逐项与同物品的本轮及历史策略对照，记录“新独立策略／原策略微调／历史策略复测”及依据。不同物品可使用相同策略类别，但各自建账。跑满额度和达标停止两种模式均可分段准备候选，先满足当前并行派发需要，再依据反馈补充；跑满额度约束总安排，不要求运行前写齐全部方案。所有候选执行前完成差异自查，只需方案级描述，不预生成完整控制轨迹。

历史策略复测、微调专项必须明确标记，不能混入“新增独立策略”的额度来凑数。用户明确要求这类专项时，单独列明有限执行预算并继续关联原策略编号。新环境下复测旧策略，不因环境版本变化自动变成新的抓法。

## 抓取部位与接触方式及方向覆盖

agent 应先识别物体具有抓取价值的结构，如主体、拉手、边缘、凹槽、凸起和连接处，再结合夹爪尺寸、碰撞模型及可达空间，分别考虑抓取部位、两指接触关系和接近路径。不能用同一部位的小幅角度调整代替策略多样性，也不能因一个方向受阻、一次抓取失败或局部结构失真，就排除整个部位；例如拉手孔不可穿入，仍须评估拉手外缘侧夹等其他方式。对有依据的候选进行有限实跑，对排除的候选记录具体几何或物理证据；尚未检查的标记为“未探索”，不能判为“不可行”。当多次尝试出现相同失败时，应重新检查模型、接触位置、进入通道和控制执行，再决定修正原策略或转向具有实质动作差异的新策略。

候选表以“部位 × 两指接触关系 × 接近通道”区分组合，记录所用资产/碰撞版本、可行依据、检查状态、实际尝试和排除证据。排除结论限定到证据支持的组合及适用条件，不能把某一通道受阻外推为整个部位不可抓；局部模型失真无法判断时记为待核实，不当作真实物体不可抓的证明。需要修复资产时沿用 [模型副本与转换规则](asset-intake-and-conversion.md)，并按 [模型结构与碰撞修复](asset-intake-and-conversion.md#模型结构与碰撞修复) 区分功能结构与生成缺陷，不修改用户原件，不为夹爪通过而改造真实几何。

两指接触关系适用于双指夹爪。使用多指、吸附等其他已支持末端时，记录其真实接触组合和承力机制，不套用不存在的两指条件，也不因本条文字就声称已有相应控制适配。

“任何部位可作为候选”不等于每个采样点都是独立策略，也不证明该点可抓。按物体坐标系描述可行的上方、侧面、前后及斜向通道，不能靠转动视角制造差异。被支撑面遮挡的底面不能直接穿透夹取；允许的真实姿态重排使区域暴露后再评估。有限实跑仍受剩余额度、每机会失败上限与成功停止目标约束，不要求穷举每个部位、方向的全部组合，也不为重复失败自动追加预算。修正原策略沿用原身份和计数，新策略仍需通过动作差异检查。

## 动作策略差异的判定标准

以下是本项目用于区分“独立策略”和“参数微调”的计数规则，不是外部机器人标准。新独立策略不能只靠编号、角度阈值、参数距离或文本相似度判断。

| 比较维度 | 可作为实质差异的证据 | 通常仍是原策略微调 |
|---|---|---|
| 接触与承力关系 | 改变几何特征区域、接触组合或夹持模式，导致约束和承力方式实际改变；例如瓶身对夹与利用把手夹取 | 同一表面小幅挪抓点，同一接触模式略调开口、夹力或指尖角度 |
| 接近与离开通道 | 相对物体采用不同的可行通道或越障/绕障方式，使关键路径、碰撞约束或夹持朝向发生实质变化 | 同一路径轻微偏转、插值点增减、加减速；仅改变世界坐标、机械臂摆放位置或观察视角 |
| 操作机制与阶段 | 从直接抓起改为经允许的真实接触调整姿态、重新夹取等另一种必要流程，改变物体状态和接触转换 | 增加无必要的等待、重复同一阶段、改阶段名称，或只调整同一动作的时长 |

独立候选至少满足一项实质差异，并有对应的关键动作、预期接触/姿态转换及约束变化说明。三项可以组合，不要求每个新策略同时改变三项；也不能故意添加无作用步骤来制造差异。

**角度变化本身不是标准。** 同一路线、同一接触和同一阶段中的轻微角度调整，按原策略修订记录；即使旋转幅度很大，若关键动作和接触关系未改变，也不自动计新策略。小角度若恰好引起真正不同的通道或接触组合，必须以这些实质变化的证据判断，不能只凭角度数值自称新策略。按物品几何、碰撞、控制精度和测量噪声设置的局部容差仅用于识别抖动/微调，不构成通用的新策略门槛；不能事后随结果改容差。

派发前的动作推演对照至少记录：

1. 最相近旧策略及相关修订/证据；比较统一到物体坐标系，排除不同机械臂位置、资产重命名及视角造成的假差异。
2. 双方接近、接触、闭合、抬升/离开及适用中间阶段的简短对照；包含关键目标姿态、接触区域、预计物体运动和反馈分支。
3. 哪个关键阶段真正不同，改变什么约束、预期解决什么问题；归类为新独立、原策略微调、重复或待核对，并给出依据。

这是一份简短的阶段/动作关系对照，不是预设整套开环轨迹，也不能用推演代替真实物理成功证据。可分段准备，只核查即将派发的候选；运行中仍由反馈决定后续动作。

执行后用真实轨迹、接触和阶段记录核对差异是否出现。计划不同但实际落成同一抓法时，保留动作和真实预算消耗，将身份修订为重复/微调或待核对，更新独立策略及停止目标统计，不继续虚增成功方案数。如果修正后不再满足停止目标，按剩余有效预算及已授权安排处理，不能自行恢复已消耗机会。

## 预算模式

本轮配置只能有明确、可计算的预算范围：

| 模式 | 规则 |
|---|---|
| 每物品额度 | 默认每物品 200 个探索策略机会，各物品独立，不能跨物品挪用 |
| 整批共享额度 | 只有用户明确要求整批 N 个机会时采用；N 是全批总和，不再为每个物品另外发 200 个 |
| 组合限制 | 用户同时明确每物品上限和整批上限时，两者同时满足，并记录分配方案 |
| 追加 | 用户明确增加额度，关联原批次及历史策略；派发前完成追加去重核查，不重复已有策略，已用额度不清零 |
| 新批次 | 明确创建新批次和新预算，保留历史身份及计数；复测旧方案不能宣称新增方案 |
| 恢复 | 延续原批次剩余额度和策略失败计数，不新建预算 |

整批共享时，执行前记录各物品初始分配与接续规则，并报告零分配或未执行物品，不能声称它们已用尽 200 次。机会只能在用户确认的范围内调度。

“200”指默认策略机会数，不是 200 次实际抓取，不是每臂各有 200 次，也不是成功与失败总次数。每物品 200 个机会、每机会最多 3 次失败时，该探索额度最多产生 600 次实际失败；提前淘汰或成功会减少实际失败数，不要求用满 600 次。

## 追加机会的去重核查

用户追加的是新的策略机会时，由 agent 依据记录确认“不与此前策略重复”，不能只请用户口头保证，也不能因为新建批次、目录或编号而跳过历史比对。

1. 在原物品稳定身份下汇总成功总表、失败总表、试次与修订记录、历史候选及当前已派发/待派发队列，注明检索范围和缺口。资产重命名或环境版本变化不自动使相同抓法成为新策略；不同物品可共用策略类别，但分别建账。
2. 每个追加候选与历史方案及追加队列内部进行动作推演对照，按 [动作差异判定](#动作策略差异的判定标准) 检查接近路径、接触/承力关系、阶段顺序、物体姿态转换及反馈分支是否真正不同。仅名称、编号、文本措辞或小幅位置、角度、速度、夹力不同不算新策略；大角度差也不能替代关键动作差异证据。
3. 保留候选编号、历史对应编号或最近似方案、实质差异、对照证据及核查结果，区分“新增独立策略”“重复”“原策略微调”“待核对”。多臂派发共享去重登记，不能让两个臂把同一追加候选分别领成不同机会。
4. 重复、微调和待核对项不得作为新增独立策略派发。历史证据不足时先核实或替换为差异可证实的候选，不声称已完全排除重复。合格候选不足时如实报告数量和缺口，不以重复策略凑满用户追加额度。
5. 旧候选尚未执行的，保留其原登记身份，按原队列及剩余额度处理，不能重新登记占用追加名额。用户明确要求重试旧策略、微调或复测时，单独记录目的、有限预算及原策略关系，不能计入新增独立策略数。
6. 追加不清除原来的预算、失败次数和成功集合，停止目标继续按已确认配置执行；需要改变目标时只确认缺失或变更项。若执行后才发现重复，保留真实消耗和结果并标明去重失误，不算新增策略，也不能删记录、退回已用机会或自行补发额度。

## 每物品成功目标与停止

每批新物体开始前，合并询问机会数和“成功多少个不同策略后换下一个物体”。记录停止模式、成功目标 K、计数范围、适用物品和用户确认；同一批可统一设置，也可逐物品设置。已明确提供的值不重复询问，未提供 K 时不自行选 1、3 等数字；“跑满额度”也必须是明确选择。恢复中断批次沿用原配置。

- 达标停止模式下，K 为正整数，并且不能超过该物品在当前预算安排下最多可能执行的独立策略数。共享预算不足以保证所有目标时明确说明分配和限制，不暗中追加额度；跑满模式不设置虚假的无限 K。
- 默认只计本批、当前物品版本、按既定抓取成功条件复核通过且已核实差异的独立策略。重复抓取、微调分支、仅执行完但未复核的候选不增加数量；历史成功不自动纳入。若用户指定以完整标准通过为目标，必须完成该范围的必要验证后再计入，不能临时降低判据。
- 成功集合与机会分配由同一协调机制维护，按稳定策略身份去重。在原始事件上记录目标、计数变化、触发时刻和停止原因；每次新派发和失败重试前检查目标，避免多个机械臂分别判断后持续补位。
- 达到 K 后停止该物品的新探索机会、新探索试次和自动补位，取消尚未执行的探索排队动作。已开始动作依据实时反馈在安全边界收尾，完成必要测量与证据保存；已约定的有限验证按其范围收尾，不借达标丢弃结果或绕开必做测试。已空闲机械臂在支持局部换物时转向下一物品，不必等待无关臂；无法局部换物时记录实际限制。
- 多臂在途收尾可能带来超过 K 的成功，全部如实保存。K 是触发停止的目标，不是可以截断记录的数量上限；不为精确停在 K 而改成逐臂串行。
- 未执行的机会释放预留，已实际开始的机会仍计为已消耗，因目标达成而收尾但未形成完整结果的记为“停止条件触发—已取消/未完成”，不能猜为成功或失败。未使用余额明确保留；每物品独立额度不转赠其他物品，整批共享额度按已确认分配规则用于下一物品。
- 可用额度耗尽且在途/待复核结果处理完仍不足 K 时，记录“额度耗尽—目标未达成”，完成复盘与归档后转下一物品，不自动加码或降低 K。正常结束按实际原因区分“成功目标达成”和“额度耗尽”；技术故障暂停、候选不足、用户叫停另列，不能冒充前两者。

## 动作中断与抓取失败分类

动作阶段、活动状态、策略终结原因与实际抓取失败计数分开记录。下列事件不能共用一个“失败”标签或计数：

| 事件 | 判断与后续 | 对实际抓取失败计数的影响 |
|---|---|---|
| 到位检查点、等待下一段指令 | 当前段已结束；进入待决策，及时依据新反馈续接 | 等待本身不增加失败次数 |
| 接近动作时限到达 | 记录未完成距离/姿态、进展、阻挡和实际执行反馈；判断有限续接、重规划或终止 | 超时本身不能证明抓取失败或不可达 |
| 物体移动、原抓点失效 | 用新物体姿态重新计算接触点和进入通道；按真实反馈决定下一段 | 重规划事件本身不增加失败次数 |
| 路线证实受阻、策略提前淘汰 | 记录具体证据、到达阶段和淘汰原因，按原预算结算并补位 | 淘汰数单列，实际抓取失败数可以为零 |
| 实际空夹、掉落或其他不满足有效抓取判据的试次 | 按当轮判据核实原始动作与状态证据，每真实试次最多记一次 | 有证据时计实际抓取失败；不能因未接触物体就一律豁免空夹失败 |
| 接口、控制或记录故障及结果未知 | 作为技术事件或证据缺口处理，保留已经发生的事实 | 不能机械地增加失败，也不能借故抹去已证实的真实失败 |

检查点、超时或重规划可与真实掉落同时发生，须分别记事件并关联同一试次，不能用暂停或技术状态覆盖已有失败证据。`rejected` 等队列终结状态以及《失败策略总表》的行数，均不能直接换算为实际抓取失败次数。

已实际开始的策略即使接触前淘汰，仍消耗原机会；不因为实际抓取失败为零就退还额度。仅计划、预留而尚未执行的候选，按下节释放预留规则处理。禁止为了避免计数而无限接近、重规划，或通过更换编号重开已终结机会。

## 策略机会与实际执行

一个探索机会绑定一个物品、一个独立候选策略和一条完整的执行记录。在开始前先预留额度；开始实际策略动作后，该机会即被消耗，直到成功、提前淘汰或失败额度耗尽。

| 事件 | 计数与后续 |
|---|---|
| 候选在执行前被发现重复或不可用 | 不算一次实际抓取，也不消耗已执行机会；标记原因，补充不同候选 |
| 机会已预留但尚未执行，因技术故障或成功目标达成取消 | 有未执行证据时释放预留；不能出现未执行成功或虚假失败 |
| 已开始后明显无效，提前淘汰 | 消耗一个机会，即使尚未累计三次失败；释放机械臂并顺延队列 |
| 抓取失败或掉落 | 每个真实试次最多记一次失败；连续多帧同一事件不能多记 |
| 同策略调整后重试 | 同机会下增修订或试次编号，失败累计不清零 |
| 实际失败达到三次 | 结束该机会，不能换编号伪装同策略继续 |
| 满足探索成功条件 | 结束探索机会，记录一个成功候选；重复抓取归入验证 |
| 复位 | 单独记录，不能抹去前序失败或拼接成同一次连续抓取 |
| 技术故障 | 单独记事件，不机械地为所有臂记抓取失败；已发生的真实失败仍保留 |

“一次试次”边界按本轮任务事先确定。策略允许的中间放置、受控松开和姿态重排，不自动等于掉落失败；意外失去控制、未达目标或违反有效判据则按约定计失败。不能事后把失败重新命名为中间阶段。

同一物品的各臂由同一预算分配器领取机会，或采用具有等效互斥效果的接口。不能只依靠对话记账。总量必须满足：

`已消耗机会 + 已预留未开始机会 + 可用机会 = 已确认额度`

可用机会降到零只阻止再领取新机会，不等于所有已领取机会结束；已预留未开始的合格机会可以按原分配执行，正在执行的机会可在原失败上限及有限动作时限内继续。达到 K、用户叫停或故障等独立停止条件仍优先处理。只有在途及待复核结果按原安排收尾后，才判本物品因额度耗尽结束。

对共享额度和每物品上限分别检查。剩余 5 个机会时最多派发 5 个新策略，其他臂进入已授权验证或等待，不能超发以凑并行数。

## 实际场景与针对性探索的计数

按 [实际场景模式](actual-scene-mode.md) 区分使用/验证、失败后的针对性探索和再次优化。新场景验证及基于失败证据的针对性探索不算重复复训，不能因此清除旧优化标记。场景执行与有限复测记录各自次数；转入探索时先核对适用的剩余额度、X和K，不自动增发200次机会。微调保留原策略身份，实质新机制/路线才按本文件差异规则登记；同一策略在新场景成功不自动增加独立策略数。碰撞内存修正前后另分环境版本统计，预算累计和真实失败历史仍保留，不用分组换取新额度。

针对性探索的目标与计数范围须绑定本次失败场景。旧批次已经达到的K及历史成功不能直接满足新场景目标；仅在新场景复测旧抓法成功，也不产生新独立策略。需要小幅修订旧策略时，沿用已确认的有限场景恢复/微调安排，不重开已结束的原机会，不占“新增独立策略”名额；未覆盖的安排才补问。真正不同的新策略按探索额度及适用K计数，场景恢复则按本轮完整任务成功条件判断。两类分别记录执行、失败与剩余上限，不以模式切换重置任一计数。

## 验证与历史方案延展

优化结果模式遵守 [复训完成标记与去重](success-replay-and-acceleration.md#空闲批量优化与完成去重)：基线复现、有限修改、结果确认属于一个有界任务，完成有优化和完成无改进均退出批量复训，不因换日期、改名或换agent重开。失败回到探索时保留既有额度与历史；普通运行使用、独立验证及再次优化分别记录，不能借验证规避已完成项跳过规则。

[成功策略提炼与提速复跑](success-replay-and-acceleration.md) 只在整批策略筛选完成后，对已复核成功集合另行有限安排；不能在筛选期间穿插。原本用于成功停止计数或标准要求的必要复核仍按原安排执行，不能因这个阶段限制推迟到无法正确判断 K。优化复跑保留父策略身份，另记修订、真实试次与验证结果，不新增独立策略、不重发或隐瞒扣除探索额度。若优化实际改变接触/承力机制或实质路线，重新按动作差异分类和授权预算，不能借“优化”免费增加新探索；配置尝试、冻结版本确认和故障恢复分别有界。

- 验证与探索分别计数。验证重复成功只增加试次和验证次数，不新增独立策略。
- 标准要求的复测数量在执行前明确。验证中的真实失败同样记录，不因称为“验证”就无限重试。
- 三次失败是探索机会的退出阈值。另行确认的标准验证按其规定的试次和停止条件执行，相关失败进入验证统计，不从探索预算中隐瞒扣除，也不能静默增加未确认的测试。验证要求冻结策略时不能边改参数边冒充同一方案的重复测试。
- 同一探索机会的微调或后续修正仍受三次失败限制。已结束或耗尽的机会不能自行重开。
- 用户明确追加历史策略微调或复测任务时，可创建新的有限执行安排，关联原策略及原失败记录；不能把该安排计为一个新的独立抓取方案。
- 没有追加授权，不为了获得好看的通过率而反复试到成功；报告所有约定试次及排除原因。

## 队列推进、完成与恢复

每个机会有明确状态：候选、预留、执行中、暂停、探索成功、提前淘汰、失败耗尽、停止条件触发取消。候选和预留不算已完成策略；暂停与取消也不是抓取失败或成功。取消时区分是否已经实际开始，保持预算守恒。

队列中的候选与开始执行的策略要能区分。开始之后不能为了替换难策略而退回机会。一次运行结束应报告额度、预留、实际开始、已完成、暂停与未使用数量，不能只报成功条数。

按本轮确认的停止模式完成各物品探索：达到成功目标后不必消耗全部上限，跑满模式才要求完成确认额度；均需处理在途结果、完成适用验证并归档，不要求每个机会机械执行三次。目标尚未达到且候选不足时补充并检查，仍不足则说明未完成数量，请用户调整后续范围，不能假报整批完成。整批收尾逐物品列明目标、实得成功数、已消耗和未使用额度、停止原因及验证状态；部分物品达标不等于全部物品结束。

在每次派发、失败、策略终结及中断时持久化状态。重启时核对仿真、事件日志和预算检查点，恢复原编号与计数。技术故障导致的证据缺口标记为未知；不能借故清空失败历史，也不能把未知轨迹算通过。

用达到或超过 200 次后的复盘要求推动 agent 检查自身问题，而不是把 200 解释成物理可行性的证明阈值。失败总结应给出已观察证据、尚未区分的原因，以及下一次有针对性的改进；责任承担与原因判断分别表达。
