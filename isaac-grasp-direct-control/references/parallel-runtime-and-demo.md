# 持续并行、后台控制与演示

实际执行、排查多臂停顿、前台演示或录制时读取。本文件约束运行行为；编写、保存或安装它不表示后台通路已打通，也不授权启动仿真。

## 三种模式的阶段边界

本文件中的实时探索称“探索模式”，批后成功方案复训称“优化结果模式”；用户调用成功策略完成具体场景任务称 [实际场景模式](actual-scene-mode.md)。实际场景按获准任务配置运行，不能自动创建40臂；失败后的针对性探索按用户确认X、预算与持续监管规则推进。探索按 [现场假设与经验积累](exploration-mode-and-experience.md) 推进；优化按 [空闲入口与完成去重](success-replay-and-acceleration.md#空闲批量优化与完成去重) 选取，已完成复训不重复领取。同一优化任务中的有限确认试次不算多个新任务；一次实际失败需要新方法时，记录原因后回到探索，不能以优化名义无界续试。

下述分段决策与续接规则用于批量实时探索；本地控制器不能在筛选中自行续播完整成功方案。仅在整批筛选按原停止条件完成且处理在途动作、必要复核与归档后，才可依 [成功策略单独优化](success-replay-and-acceleration.md) 开展已授权的有限反馈复跑：本地控制器在实测参考、状态条件与保护限值内推进，agent 处理优化与异常，保留各臂独立进度及必要检查点。复跑不冒充探索；不从尚在筛选的批次抽出先成功的策略提速。筛选期 FPS 维护、记录与既定有限复核不受此限制影响。

## 每批开跑前快速规则复核

每次新的批量训练正式派发前，agent 必须快速重新查阅实际加载的当前 `SKILL.md`，并读取本轮模式、预算及当前问题所需的引用条款。连续多轮训练中的下一批同样执行；暂停恢复、跨天、对话/上下文恢复或重启后重新开跑也执行。不能仅凭上一批已读、旧摘要、记忆或“已知规则”的声明跳过实际查阅。三种模式中的批量任务均适用，但按各模式自身的配置与计数核对，不把探索默认值套给其他模式。

复核使用以下简短要点，不另外撰写长篇计划：

- 本轮模式、物体/场景及资产版本、有效标准和已确认配置；用户选择的X、不同策略分配或明确的复测安排；剩余额度、实际失败累计、K或本模式的停止目标与计数范围。既有明确选择沿用，不重发预算或反复问用户。
- 现场反馈和定位时效、动作续接及独立并行、实质动作去重、失败分类与补位、FPS和持续监管、模型/碰撞变更授权及前台控制归还。优化仍待整批探索收尾，实际场景失败按原策略针对性探索。
- 真实证据、trace和归档状态，以及本轮涉及的数据回传等授权；规则复读不构成新的上传、安装、修复模型或发布授权。未涉及的功能不强行展开或要求重新配置。

在现有trace或批次启动记录中保存复读时间、实际读取的技能路径与版本/哈希、必要引用、本批次/配置身份、简短核对结果和发现问题的处理状态。记录须依据真实读取与检查，不能提前填写“已复核”；发现影响本批执行的缺项或冲突时先处理相应新派发，旧预算、历史证据和在途动作不静默改写。新规则与冻结配置冲突时说明作用范围，遵循用户有效要求处理，不能读到新文件就擅自重置实验。

复读只占启动前一个短检查段，不穷读无关引用和历史记录，不提前准备整批长轨迹；同批正常短动作续接或单臂补位不重复整篇复读，仍执行各自的实时差异、预算和反馈检查。必要时可在其他臂继续有效授权动作期间检查，不能为复读设置全场屏障。运行中出现规则/配置变化或相关遗漏时，及时重查受影响条款。一次复读不替代持续监管，也不证明运行程序已自动实施启动检查。

## 每批启动与持续监管

1. X 就是用户在启动信息中选择的同时运行机械臂总数，默认建议为 40 台，保留“本批同时启用多少台”的询问环节。用户已明确数量或明确沿用适用配置时直接采用，不重复询问；同批续跑沿用原 X，不能因隔天、换对话或读取新技能就套回默认值。改变数量有明确依据和用户选择，更新唯一配置及原因。
2. 同批探索启动前，将 X 台分别绑定到 X 个已完成实质动作差异检查的策略，记录机械臂、物体/资产版本、父策略及修订、机会身份和差异依据。按 [动作策略差异](strategy-and-budget.md#动作策略差异的判定标准) 比较接触/承力、通道和操作机制，核对适用历史成功、失败和当前队列；不能只换名字、编号、环境位置或物体副本。微调仍归父策略，不把一个抓法复制到 X 台凑数。明确安排的验证复测另列，不能混报为 X 个不同探索策略。
3. 在本轮定义的有限启动窗口内批量派发并核实实际开始，使 X 台在共同仿真时段独立推进；不要求每条指令绝对同一时刻到达，也不建立后续逐阶段全场屏障。保存每臂真实开始与活动区间，启动失败/未开始单列，不能以 X 个场景、进程存活、已预留或 active 标签报告 X 台已工作。
4. 候选、剩余额度或已核实能力不足以支持 X 时，先补足可补足的独立候选并守住预算；仍不足则说明实际数量和原因，按已有授权的收尾规则或用户调整处理，不复制策略、超发预算或静默减臂。已达到 K、额度耗尽、正常收尾与故障造成的数量下降分别记录，不为维持数字无限补位或重开成功策略。
5. 每次新批量开跑、跨天续跑、恢复对话/上下文或程序重启，在下发本轮新的动作前，先按 [快速规则复核](#每批开跑前快速规则复核) 重新查阅当前技能入口及必要条款，再读取持久化本轮配置、预算账本、分配表和未完成事项，核对有效规则版本与实际控制实例。结合最新现场观测确认仍在运行、已停或故障，避免重复实例和重派在途动作。原数量、策略身份、预算及失败记录沿用；旧记录的 enabled 标记和旧时间戳不能替代新监管证据。规则更新与冻结实验配置有冲突时先说明适用范围，不静默重写历史或在途动作。
6. 已授权运行期间，agent 持续履行监管：按本轮配置的有界检查周期及到位/超时/物体移动/终结/补位等事件，读取新反馈并核对每臂阶段、活动、实际并行、动作差异、待续接与补位、预算/停止条件、FPS和记录完整性。需要动作时及时作出并执行有限决策，保存核对结果与处置；发一句状态更新或重复读旧日志不能算完成监管。检查周期符合观测时效和开销，不把特定秒数设成所有环境通用值。
7. 持久记录监管者和唯一控制实例身份、规则/配置版本、X、当前分配、每臂检查点及未完成工作、最后有效反馈与最后监管检查的时间/物理步、监管过期阈值和恢复上限。仅进程心跳不证明反馈新鲜或决策续接完成；单独区分监测存活、反馈有效与任务推进。跨进程或重启后的时钟基准必须可辨，不能拿上一会话的单调时钟值当新会话的新鲜样本。
8. 监管或反馈过期、agent暂不可用、实例失联时，通过实际已具备的本地控制保护停止依赖失效反馈的新动作，现有动作只在原授权时限和有效条件内执行，到期按预设受控保持/暂停处理；可隔离时其他受监管臂继续。保存中断起止、缺口、受影响范围及恢复点。恢复须重新核对现场、唯一控制者、待执行命令与预算，不补造失联期间已监管的结论，不无限重启或追加机会。
9. 不依赖用户隔几天再次提醒才能恢复监管。可靠的跨会话持续监管需要已实现的本地监督、过期保护及状态恢复能力；先核实实际接口和运行证据，缺失则标明“监管未接入/失效/待恢复”，按现有有效能力处理，不能仅凭SKILL承诺agent离线仍持续监管。本规则更新不开发这些功能，不创建定时任务或启动训练；开发需求与执行验证分开。
10. 结束时报告 X、已实际启动/执行的不同策略数、各臂活动及并行证据、监管覆盖区间、异常/失联区间、续接与补位结果、剩余额度及未解决事项。实时监管结果与物理成功复核分开；不足 X、缺失记录或监管中断如实标明。成功策略提速仍只在整批筛选完成后另行安排，不能因加强监管而穿插到筛选中。

## 后台链路先于前台操作

- 默认使用后台接口批量读取状态和失败事件，校验数据时间戳、物理帧、机械臂身份与新鲜度。旧日志可用于复盘，不能当作实时观察。
- 在已有运行授权内核实下发、接收与实际执行反馈，保持唯一控制者。读写通路的实测结果关联当前实例和会话，不能以接口存在或发送成功替代闭环验证。
- 先检查现有仿真实例及可用控制入口，复用合适实例，保留物品、标准、预算和历史数据。不能为了演示另开重复进程，也不能无依据终止现有任务。
- 本轮配置明确观测时效、短动作授权时限、反馈等待上限和本地故障处置方式。接口不能满足时报告差距，不假称实时控制已经实现。
- 实时闭环演示先核实后台链路，但链路有效不自动意味着需要切换前台。是否接管按下节逐段判断，不能为了例行截图无必要地激活窗口。后台通路未建立时，不用前台画面冒充已完成闭环；恢复接口必须借助界面时先说明具体目的，并核对已有授权是否覆盖，仅在缺少授权时补充确认。

## 前台控制必要性与控制权归还

1. 默认通过后台接口控制机械臂、读取状态、监测性能和记录数据。实时控制机械臂不要求持续接管用户的鼠标、键盘或前台窗口。

2. 每次接管前，明确本次前台操作的具体目的及完成条件。仅当操作必须依赖界面，或需要核对实际显示效果时，才短暂接管。能够通过后台接口完成的操作，不使用前台控制。

3. 将前台操作限制为一个明确、短小的操作段。完成点击、设置、视角调整或必要取证，并核验结果后，立即结束前台接管、归还控制权。不得等到整个训练或排查任务结束才归还。

4. 阅读代码、修改程序、分析日志、统计数据、思考下一步、等待仿真或测试完成期间，不得持续占用用户的鼠标键盘，不得无必要地激活窗口或反复抢夺焦点。

5. 归还控制权与停止后台任务分别处理。结束前台操作后，保留仍获授权的仿真、后台控制和监测任务；不得为了释放桌面而擅自终止它们。

6. 不得把“没有继续点击”当作“已经归还控制权”。应依据工具提供的状态或可观察结果确认接管已结束；无法确认或工具不支持独立释放时，如实说明限制，不得声称已归还。用户要求收回控制时，立即停止新的前台输入。

7. 出现窗口反复跳转、画面闪烁、黑屏或用户操作被打断时，记录异常发生时间及对应操作，停止无必要的重复前台操作，优先通过后台证据定位原因。不得未经验证将异常解释为正常现象，也不得只凭 FPS 提升宣布优化完成。

8. Trace 至少记录：接管原因、开始时间、实际前台操作、完成条件是否满足、结束时间、控制权归还状态及相关异常。归还状态必须区分“已确认”“未确认”“失败”，不得以任务仍在运行作为持续接管的理由。

## 各臂独立推进

- 批量观察和批量下发用于减少交互开销，各臂不必等待同一阶段结束后才推进。不能以单臂决策、复位或淘汰作为全场停顿的默认理由。
- agent 根据反馈决定每臂下一段动作；本地控制器在已授权目标、时限和限值内高频执行并处理即时故障。等待 agent 时，仍有效的已授权动作可继续，不能自动续上未经决策的完整抓取流程。
- 授权动作结束或反馈过期的臂进入预设受控保持、隔离或等待。其他臂只有在各自授权和反馈仍有效时继续。全局反馈失效或确实无法局部隔离时允许必要全场暂停，并记录实际原因。
- 分开记录动作阶段与活动状态。活动状态至少能区分运动、有效保持、测量、等待决策、复位或补位、已隔离或失败、完成。
- 有效保持须有任务要求、有效控制目标及持续物理反馈支持。仅因画面静止不能判为闲置；仅因夹爪仍闭合也不能把决策等待改标为有效测试。

## 检查点后的动作续接

1. 到位、短动作时限到达、物体移动或补位复位完成时，立即产生该臂的待决策事件，关联最新观察及动作结果。agent 持续处理这些事件，批量提交各臂不同的下一段短动作；不能只完成复位或留在检查点，便视为推进完成。仍满足继续条件的臂不等待无关臂。
2. 到位检查点只表示该段运动结束，不表示已接触、夹持或成功。核对物体、夹爪与可用接触反馈后，再决定继续接近、闭合、调整或终止；不得无条件自动闭合，也不依赖过期抓点继续动作。
3. 短动作超时后，区分实际物理执行时间、通信等待和 agent 决策等待；结合位置/姿态误差变化、碰撞、关节或驱动状态判断仍在推进、停滞受阻或控制未执行。仍有明确进展且条件有效时，可由 agent 授权有限续接；持续无进展时先定位或淘汰。沿用本轮动作总时限及有限恢复上限，不能反复重置计时把动作无限延长，也不能凭一次超时宣布不可达。
4. 触碰导致物体移动或旋转时，按 [物体移动后的定位与目标更新](#物体移动后的定位与目标更新) 及时读取新位姿、使失效的旧目标退出执行，并更新接触位置和进入通道；不沿用旧世界坐标。重规划继续原机会和失败计数，不另赠额度。
5. 本轮配置给出符合当前接口能力的决策等待告警阈值和有限处置上限，并分别记录墙钟与仿真时间。等待超限时定位观察、决策、派发或执行确认的阻塞点，优先补齐可执行的续接；无法恢复则明确受影响范围。守住反馈新鲜度与授权边界，不能靠取消检查点、无限续播或自动扩预算来掩盖调度问题。

## 物体移动后的定位与目标更新

1. 在接近、接触、闭合前后及必要的中间操作中持续读取同一环境、同一目标物体的最新位置和朝向，保留时间戳、物理帧号及资产/复位身份。触碰、推挤、滚动或旋转使原目标失效时，及时更新定位；不能等该段结束或超时后才检查，也不能继续把初始世界坐标当作当前抓点。
2. 尽量用目标物体或对应部件的局部坐标记录抓取部位、接触关系和关键接近目标。每次重新定位后，用当前部件位姿换算到控制接口要求的世界坐标或机器人基坐标，再计算进入通道与可达性。须同时更新平移和朝向，核对世界、环境、物体和机器人基座之间的变换；不能把其他并行环境的物体姿态套给本臂，也不能遗漏或重复叠加环境偏移。世界坐标可以使用，但必须由适用的新观测生成。
3. 检测到物体变化已使当前目标或通道无效时，使相关旧动作目标失效，核实尚未执行命令的取消/替换状态；对正在执行的动作采用已定义的受控保持、停止或回撤，再依据新反馈派发下一段。记录控制接口实际确认，不能把取消请求当作取消完成。只处理受影响臂，其他臂在各自反馈和授权有效时继续。
4. 重新核对物体状态、接触位置、支撑关系、进入通道及碰撞约束，再决定接近、调整、闭合或终止。物体仍在移动时，按实际反馈选择有限跟随或等待稳定；闭合前复核有效性，不能追逐过期目标盲目闭合。位姿变化容差、反馈时效和有限重规划上限依据本轮几何、测量和控制能力配置，不设置与所有物体通用的固定距离或角度，也不因微小噪声无限重启。
5. 已建立有效持握后的跟踪与抓取前重新定位分开处理。持续检查物体相对夹爪的实际漂移，但不能每帧重定义“理想夹持相对位姿”来吸收滑移或生成相互追逐的目标。确需重新夹取或改变接触关系时，以新阶段及其证据明确记录，原漂移/掉落事实保留。
6. 反馈缺失、过期或坐标系不明时，不执行依赖未知定位的新动作，明确阻塞并按有限恢复规则处理。重新定位沿用原策略、机会和失败计数；实际空夹、掉落按证据另记，重规划本身不是新策略或新增失败。Trace关联物体移动前后的观测、旧目标失效、取消/替换反馈、新目标及下一段实际执行，未知状态不补造。

## 淘汰与补位

沿用 [策略与预算规则](strategy-and-budget.md)，及时处理“隔离与记录 → 必要复位 → 选择已检查的不同候选 → 预留剩余额度 → 下发短动作 → 确认实际开始”。独立操作可在同一批次中调度，不能增加无意义的全场屏障。

原机会终结、剩余额度、候选身份和新机会预留都要可追溯；微调不清零失败，换策略不重发预算。复位只作用于需要恢复的环境，不扰动其他臂的有效测试；平台不支持局部复位时如实报告限制。

预算耗尽、候选不足、复位受阻或接口故障时，显示对应原因及剩余工作。补位完成以新策略实际动作开始为准，不以排队、预留或发送成功代替。没有额度时不能为凑满并行数量启动新策略。

每次补位与探索重试前同时检查该物品的成功停止目标。达到已确认的 K 后停止其新探索，处理在途动作、释放未执行预留并记录剩余额度；空闲位置可按授权顺序切到下一物品，其他物品继续。因达标停止补位是正常收尾，不能当作调度卡顿，更不能为凑满原物品的臂数继续耗机会。在途多臂额外完成的结果全部保留，停止与计数细则见 [策略与预算规则](strategy-and-budget.md)。

## 持续并行的实测证据

复用 [Trace 执行追踪规则](trace-and-replay.md) 的事件和原始状态，至少能够重算：

| 指标 | 口径 |
|---|---|
| 仿真推进时间 | 同一运行段内原生物理时间推进量；复位前后分段，不乘机械臂数量 |
| 实际耗时 | 同一观察窗口的墙钟或单调时钟耗时，说明是否包括启动和加载 |
| 全场等待时间 | 因调度或决策等待导致全局物理暂停，或所有本应可推进的臂等待决策的区间；分列原因，重叠区间只计一次 |
| 各臂活动时长 | 状态转换对应的运动、有效保持、测量、等待、复位等区间；不可把全部静止时间统算成等待 |
| 动作续接延迟 | 每臂检查点或需要重规划，到下一段实际开始的墙钟/仿真耗时；区分等观察、等决策、等派发和等执行确认，未续接项仍保留 |
| 补位延迟 | 原策略终结到该探索位置下一策略实际开始的耗时；记录墙钟与仿真时间，区分隔离、复位、选策、派发及执行等待 |
| 实际并行 | 同一仿真时段内各臂分别执行的策略和活动状态，区分运动与有效保持、测量；物体与策略编号能够追溯 |

同时报告配置/场景臂数与观测窗口内各臂真实活动状态及其持续时间。场景中有多台臂、任务已预留或处于 active 标签，不能单独证明持续并行；单帧快照也不能代表整轮表现。没有执行记录的臂需核实是等待、完成、无候选、预算终止还是其他状态，不能直接全部归为等待。

有效持握和测量不算无效全场等待；未完成补位的事件标记仍在等待或被阻塞，不能从统计中静默删除。配置和场景不可比时说明限制，不宣称优化前后存在确定收益。

完成相关修复后，在既有授权与预算内实际展示不同策略同时执行、单臂失败或淘汰后隔离、其他臂继续、下一策略补位。修复结论分别列出规则已更新、程序已改动和运行已验证；只有运行记录证实续接及补位满足本轮要求，并核对可比条件下的改进与剩余限制，才可声称对应问题已修复。没有自然发生可用于验证的事件时标记未验证；如需专门故障演练，另行明确安排，不能通过暗中制造失败或剪辑拼接补证。

## 演示、录像与交付

运行全过程按 [画面与录像规则中的持续性能监管](visual-quality-and-recording.md#持续性能监管与优化) 采样和处理退化，包括尚未演示的后台运行阶段。把性能指标关联场景、物品、并行数和动作阶段；不能只在用户抱怨卡顿后或录屏前检查一次。

- 以后台实测为依据选择能清楚显示多臂和状态的视角，必要时增加局部视角；截图只作辅助证据。
- 用户要求录像时，可以使用授权范围内的后台录制，或明确指导用户录制。先试录短片，在不破坏实时反馈和测量条件的前提下选择当前硬件可稳定支持的高画质和流畅帧率，不虚构固定性能保证。
- 记录分辨率、实际帧率、掉帧、录制开销及时间基准。质量和流畅度冲突时先优化可独立调整的渲染与录制开销，说明实测取舍，不静默降低物理或验收精度。
- 保存原始录像并关联 trace 时间区间。剪辑展示另存并标明用途；加速、补帧或删掉失败片段不能当作真实运行性能或完整测试证据。
- 按 [记录与归档规则](records-and-archive.md) 报告已执行、复核结果、中断或证据缺口，以及整批验证是否完成。明确哪些运行环节已经验证、哪些只是完成代码或规则修改。
