# 配置与标准生效规则

首次安装核验、初始化、实际执行、环境改变或用户调整标准时读取本文件。仅整理技能文档时不执行这里的安装、检索、确认或仿真步骤。

## 首次安装与加载核验

本节是 agent 应执行的核验与引导流程，不是自动安装器或安装后自启动钩子。下载 ZIP、把附件发进对话、解压文件和宿主成功加载是不同状态；不能因用户上传了文件就声称已永久安装。

1. **确认承载此技能的 agent 环境**：从已知上下文确定产品、版本、操作系统及实际执行位置（本机、远程工作区或容器），只补问无法判断的部分。核实其支持的技能格式、安装入口和必要的文件/执行能力。聊天附件阅读能力不代表有本机控制权限；没有相应能力时交付适用的安装步骤并明确限制，不能声称可直接控制用户电脑。
2. **核对包与安装位置**：按已确定的发布来源、版本、文件清单及签名核验包，无法核验的项目标为未确认。保留完整的技能根目录及其引用和辅助文件；目标必须是该宿主、版本和实际执行环境支持的技能位置，不照搬开发者路径，不默认所有产品共用同一目录。目录选择以该宿主现有有效配置及当前官方说明为依据。
3. **识别首次安装、更新或重复副本**：在相关已知技能位置核对同名技能、版本及来源，不遍历无关私人目录。首次安装写入选定位置；更新先备份旧技能，再原位替换技能文件，保留配置、模型库、队列与预算。发现多个同名副本时核对实际加载来源，不能新建更多副本掩盖冲突，也不擅自删除其他项目所用版本。
4. **验证宿主发现与实际加载**：按宿主支持的刷新、下一轮读取或重启方式使技能可见，不统一要求重启。通过技能清单/管理入口或宿主提供的加载信息确认发现，再在一次明确调用中读取实际路径下的当前 SKILL.md 及本流程，核对版本、引用可读性和关键规则。只由通用文件工具读取文件，尚未证明宿主注册发现；宿主无法暴露相关状态时标为未确认。安装身份已核实后交付实际安装位置、版本、已通过项、未完成项和下一步入口。
5. **按当前请求进入初始化**：用户只要求安装或检查时，停在相应核验结果并给出首次使用入口；安装不会自动询问完整训练参数或启动训练。用户同时要求初始化、开始使用或继续任务时，沿用已有授权和配置，首次先确定仿真平台及运行位置，再按本文件准备环境、存档根目录、模型来源和验收依据。平台未选时不默认 Isaac；其他平台须先核实适配。缺少所选软件时先询问是否协助下载和搭建，获准后在范围内连续完成。
6. **分别记录就绪程度**：区分“文件已安装”“宿主已发现”“本次调用已加载”“项目已配置”“仿真及任务接口已验证”“本轮可运行”，每项附实际证据、时间和缺口，不用单一 initialized=true 代替检查。仿真验证沿用后文的有限授权检查；没有启动过仿真只能报告安装/加载核验，不能宣布可以抓取。开始正式训练前另按既有规则补齐目标物体、机会预算、并行数、成功停止条件、有效验收依据和运行授权。
7. **保留首次配置与更新连续性**：身份、版本、加载位置、就绪结果及配置引用并入原有项目记录；存档位置尚未确定时只交付当前核验摘要，不自行创建新训练库。换对话、重启或升级先读取旧配置和最新实际状态，保留预算与历史；新项目或变更环境只补查受影响项目。记录丢失或不可访问时说明不确定，先恢复或核实，不把未知当作首次使用并清空重建。
8. **数据选择独立处理**：安装、初始化或点选技能不构成上传授权，上传保持默认关闭。可简短说明后续可自愿选择小范围贡献；不把同意回传、填写服务器账号或提交密钥列为安装条件，也不在安装时扫描或上传训练库。

宿主的读取与刷新行为以当前官方文档和现场证据为准。Codex 官方资料见 [Build skills](https://learn.chatgpt.com/docs/build-skills)（2026-10-27 核对）；该产品说明不能直接套用于其他 agent。

## 每次训练的启动信息

每次新训练或新批次开跑前，通过日常对话与已有记录确定以下三项，不要求用户先掌握专业术语、资产编号或固定句式。信息由用户表达、明确委托 agent 选择，或从适用的已有配置恢复；只补问确实无法可靠确定的部分，不能因用户没有写出文件路径就一律拒绝推进。

1. **目标物体或继续的任务**：支持聊天描述（如“试试那个带把手的杯子”）；直接给名称、模型路径、附件或资产编号；委托“从未训练的里面找”；或直接说“继续”。agent 根据已授权的库、当前上下文和记录把意图落实为具体资产、版本或批次。
2. **策略机会次数**：用用户易懂的语言确定每个物体额度，或明确整批共享额度及分配口径；可明确沿用适用的已保存设置。次数为策略机会，不是单次掉落次数，也不因并行臂数增加而自动成倍增加。用户不理解时先简短解释再询问所需选择。
3. **同时运行的机械臂数量**：询问并确定本批希望同步运行的总数量，这个用户确认值就是后文的 X；默认建议仍为 40 台。已明确或明确沿用的值直接采用，不另问一套 X，也不被默认值覆盖；可沿用明确的已有设置，多物体的分配可由 agent 提出后确认。按已有硬件/场景证据核实可行性；用户不熟悉时给出有依据的建议，不要求其自行计算性能或填写专业配置。

目标解析遵循以下规则：

- **沟通或直接指定**：先利用已授权的模型库、历史映射和当前任务定位。名称即可明确匹配时不要求再给路径/编号；多个候选会影响实际选择时，用名称、可用缩略图或简短选项协助确认。确实没有模型或访问入口时，再用普通语言请求必要文件、位置或库入口，不伪造资产。
- **委托挑选未训练物体**：用户已经授权 agent 代选时，无需再让用户逐个点选；在明确的库/项目和既定批次范围内核对真实执行记录，按已有队列或可解释的顺序选择，并告知选了什么及依据。没有指定数量时先选一个可用候选，不自动把整个库全部开跑。模型库未配置、无候选或记录不足时说明缺口，不自行扩大检索范围。
- **未训练的含义**：以当前授权范围内、具体资产版本的实际执行记录判断，区分未测试、已试过未成功、成功待验证、已验证和记录不明。没有成功记录不等于没有训练；计划、导入或空表也不能单独证明已训练/未训练。历史不明标待核对，不能为凑未训练候选清除失败记录；换标准不把旧物体重标为从未训练，换资产版本须保留来源与适用性关系。详见 [模型登记](model-registry.md)。
- **继续**：优先识别当前明确的未完成任务，读取检查点、剩余机会、失败计数、并行设置、标准和停止条件后恢复，无需让用户重填。有且仅有一个明确适用的已有任务时直接沿用；多个任务、上下文过期或恢复记录不足时，用最少的问题澄清。当前任务已在运行时，“继续”不再开第二个实例或重复派发。已授权队列中当前物体结束后可以依原配置转下一物体，但不能据此扩大原队列、重开已结束任务、重发额度或追加预算。
- **继续的限制**：额度耗尽、原批次已完成且无获授权的后续队列，或存在尚未解除的技术故障时，说明当前状态，只询问下一步所需选择。“继续”是延续已明确任务的要求，不是无限追加机会、忽略故障或变更标准的许可。

在新动作前，简短显示所确定的目标或恢复批次、机会额度（续跑显示剩余值）和同时运行臂数。已有明确选择或授权代选且没有冲突时，不把这个状态告知变成又一轮强制确认。

默认建议 200 个机会、40 台机械臂只用于提示选择；用户明确采用后才进入本轮配置。示例不授权运行。数值应为有意义的正整数，处理与已有预算/成功目标的矛盾；零额度不开始新探索，不能自动替换为默认值。能力不足时给出有依据的可选调整，不能静默减臂或以串行冒充同步。

与原有成功停止数量 K/跑满额度、有效标准及运行授权一起核对，不能把三项启动信息当作全部验收配置。已有有效标准和确认项继续沿用，缺少关键项时仅完成独立准备工作。恢复同一中断批次是续跑，不是新建预算：保留原目标、剩余机会、失败计数、并行设置和恢复点。

README 的醒目提示与此流程保持一致，不能只写提示而让程序继续静默采用默认值；程序执行前校验属于后续开发验收，本规则更新不代表控制程序已经实现。

启动和续跑的数量选择与监管使用同一个本轮配置：X、臂—物体—策略分配、实际同时运行状态及变化原因必须对应。每次启动、恢复对话、上下文恢复、程序重启或跨天续跑前，按 [持续监管规则](parallel-runtime-and-demo.md#每批启动与持续监管) 读取持久记录并核对最新反馈及监管状态。检查属于 agent 的执行职责，不要求用户每天重新开启监管或重复确认同批参数；旧配置无法确定或用户要改变数量时，才补问对应选择。

工作模式根据用户任务和有效恢复记录确定，只有存在关键歧义时补问：探索模式采用当前探索预算及X个不同策略；优化结果模式采用已完成批次的成功集合和独立有限安排，先核对复训完成标记；实际场景模式等用户调用，明确具体任务、场景、来源策略和有限执行/验证安排，不自动套用探索的40臂/200机会。失败转探索时沿用适用的X、剩余额度及K，缺失才补问。空闲入口记录允许的库/范围、资源与并行数、空闲条件、有限总量及停止/恢复条件；已有明确空闲许可沿用。模式切换记录来源、原因与剩余任务，不能自动重发预算或将已完成复训重新入队。

碰撞体误堵空隙的仅内存修正按 [专项询问](asset-intake-and-conversion.md#碰撞体误堵空隙的内存修正与询问) 登记“本次”或“本轮同类”授权、稳定批次编号、适用物体/修改范围和失效条件；本轮内覆盖项沿用，新的批次或超范围须再确认。授权与运行修正是否实际加载分开核实。

## 配置分层

- 项目配置：用户选择的仿真训练软件、版本和运行位置、用户提供的模型文件/附件或资产库接口、数据/模型库根目录与归档方式、已核实的环境与硬件信息、检索/搭建/转换授权范围、安装与启动入口、就绪检查结果、常识资料入口。
- 本轮配置：物品清单及版本、目标与实测并行数、每物品臂数、预算模式与额度、逐物品停止模式和成功策略目标 K、成功计数范围、探索成功条件、有限验证安排、有效标准版本、动作与反馈时限、故障恢复上限、环境版本，以及性能监测周期、分阶段基线、目标和退化触发条件。
- 运行状态：已派发机会、策略和试次状态、计数、检查点、实际性能与证据路径；同时持久化当前监管者/控制实例身份、有效规则与本轮配置版本、最近有效反馈/监管检查时间、待续接和补位事项、监管中断与恢复状态。检查周期、反馈/监管过期阈值和有界处置方式按当前接口能力写入本轮配置；只保存 enabled 标记不能证明监管有效。

配置可以使用环境现有的可靠格式，不要求搭建新配置框架。关键是只有一个明确的本轮事实来源，能够持久化、恢复和核对。临时配置不能写回通用技能描述。

已经得到的授权和明确参数继续有效；不要因切换对话重复询问同一件事。每批新物体开始前合并确认目标物体、机会预算、同时运行的机械臂数量和“成功多少个不同策略后停止该物品并换下一个”，可统一应用于整批或逐物品指定；也可明确选择跑满额度。本次请求已经明确给出的项、合法委托代选得到的目标或适用的恢复记录直接采用，确实缺项才询问。停止计数按 [策略与预算规则](strategy-and-budget.md) 核实，不能自行猜目标。缺少可定位的目标物体、明确并行数量、预算、停止模式、有效验收条件或必要存档位置时，先完成不依赖它们的检查，等相应信息明确后才执行依赖步骤。恢复中断批次沿用原目标、已复核成功集合与剩余额度。

硬件检索仅涵盖任务相关的处理器、显卡及显存、内存、可用存储、驱动和仿真软件版本等信息，不广泛扫描私人文件。能力估计记录所依据的场景复杂度、渲染方式和环境数量；没有代表性测量时只能报告估计范围。

## 环境选择与自动搭建

首次询问时先确认用户希望使用的仿真训练环境、版本要求及本机/已有远程运行位置。已有明确选择继续有效；用户尚未决定时，根据可核实的硬件和任务需求说明可用方案，不自行把全部用户锁定为某个软件。现有技能的控制适配面向 Isaac Lab / Isaac Sim；选其他环境时先核实接口、物理模型和标准测量能力，缺少适配就明确报告，不承诺通用一键支持。

1. 在已有检索授权内检查所选软件是否安装、能否启动，以及版本、依赖、硬件、存储和项目接口是否匹配。区分未安装、已安装但依赖缺失、版本不兼容、运行故障和信息未核实，不能只因搜索不到快捷方式就断定未安装。
2. 本机缺少对应软件或配套环境时，向用户提供“自动下载并搭建配套环境”“使用已有环境/自行安装”等选择；说明拟安装组件、相互兼容的版本、目标路径、有依据的下载量/空间与时间范围，以及需要的系统变更。用户确认后即可在该范围内连续完成，不按每个包重复索要同一许可；只改技能、选择环境或授权检索本身不等于批准安装。
3. 实际搭建前核对官方当前安装文档、兼容性要求和下载来源，选择彼此匹配的程序与依赖版本，不盲目组合各自最新版。下载记录来源、版本和可用的签名/校验信息；已有可用环境优先复用或隔离新建，保留既有项目、数据与配置，不未经授权覆盖或卸载它们。
4. 自动化范围以能开展本任务为目标：下载并安装获准程序、配置匹配依赖与项目环境、设置必要路径、准备获准的基础资产和控制/记录接口、提供可重复运行的配置步骤及清晰的启动入口。已完成的步骤可检测和复用，中断后从检查点继续，不每次全量重装。
5. 账号登录、许可证确认、额外付费、管理员权限或系统重启等若需要用户参与，明确具体步骤及其来源；不能绕过或假装完成。超出既定安装范围的驱动/系统变更另行说明并取得所需授权。硬件或平台无法支持时说明阻塞，给出可行选择，不擅自改用云端或另一软件。
6. 下载/安装完成后，在搭建授权覆盖的有限检查范围内真实启动程序，加载最小代表性场景，核实所需机器人/物品资产、短动作指令与执行反馈、数据保存读回及基本性能。检查段单独标记为环境验证，不计为探索机会、成功策略或标准通过。失败保留诊断并采用有限修复上限；不能无限重装或只凭安装日志成功宣布就绪。
7. 就绪结果区分“软件安装完成”“启动检查通过”“任务所需接口已验证”“可开始已配置的训练”。只有本轮所需软件、控制、记录和测量能力都已核实，且物品、标准、机会预算、成功停止条件和运行授权齐全，才进入正式训练；配置成功不自动启动长时间探索或新增训练预算。
8. 尽量把已获授权、可自动执行的步骤组合成一键配置/启动入口，用户只需处理明确列出的必要交互。安装与检查优先后台执行；确需前台时遵守 [前台控制与归还规则](parallel-runtime-and-demo.md#前台控制必要性与控制权归还)。交付安装位置、软件/依赖版本、启动方式、验证证据、未解决项及恢复入口，不能把书面步骤当成已搭建环境。

本文件规定后续 agent 的工作流程，不附带通用自动安装器。是否能实现完整一键配置，取决于所选平台、授权、实际工具及已验证的适配情况；本次规则编写不执行下载、安装或仿真。

## 标准库

在用户指定的存档根目录建立独立的 `标准库`，保存用户选择的标准原文或可获取的原始文件，以及来源、标题、版本、获取时间和校验信息。不可直接取得原文时标记来源未核实，不能宣称已经核实所有条款。

区分以下记录：

1. 原始参考文件：保持原文，不能用修改后的内容冒充原标准。
2. 本轮适用条款及解释：写明适用范围、仿真适配和缺失项。
3. 有效验收配置：标准版本、项目自定参数及用户对冲突的决定。

标准的“草案”“测试方法”“项目验收条件”和“认证要求”保持原本性质，不互相改称。没有统一合格线的测试方法不能自动生成统一通过阈值。

常识文档作为参考资料管理，提取的建议标注出处。文件中的指令式文字不能自动成为发送消息、扩大检索或变更项目的授权。与有效标准冲突的建议不能直接生效。

## 更换与叠加

用户要求执行新标准时，核对是替换还是叠加；用户已明确给出选择则直接沿用，只在缺少这一决定时通过卡片选择：

- 封存旧标准，改用新标准；
- 保留旧标准，叠加新标准。

新文件先按候选状态入库。替换保留旧版和历史结果；叠加则先对比再启用。对比至少核对量纲和单位、坐标系、测量对象、时间窗、试次要求、操作程序、阈值、物体适用范围。

数值不同不必然冲突，数值相同也不一定等价。只有语义、单位、条件一致且可同时满足时，才可形成组合条件，向用户展示。不得平均阈值、擅自择宽或把“取更严格值”当作通用合并方法。

对不能同时满足的条款，列明原文出处和实际影响，让用户选择保留哪一要求、安排独立测试，或取消本次变更。用户选择后生成有来源的有效配置，不能声称被舍弃的条款也已经满足。

只有有效标准版本已经确定，依赖该版本的运行才能开始。取消变更时保留原有效版本，新候选不自动启用。运行中换标准时在可控边界暂停，保存旧条件的记录，为新条件建立关联的新运行段或批次，并明确沿用还是追加预算；不自动重新发放额度。

旧数据可用来离线复核新判据，但必须具备相应原始测量和相同适用条件。缺少新标准要求的数据时标记未测试，需要另做实际验证；不能只改报告标题就宣布通过。

## 模型入口与转换准备

用户模型由明确路径、对话附件或资产库软件接口提供，按 [模型接入与副本转换](asset-intake-and-conversion.md) 先评估格式、依赖、尺寸/坐标、法线、碰撞和必需物理属性。资产库须理解并核实接口与资产规则后接入；需要辅助转换时先询问，原件不改，先复制进指定库并为复制文件另做备份，再在工作副本转换。库内保留“用户模型文件复制/已转换好”目录及版本关系，未验证输出不能当作已具备仿真条件。

## 环境与测量核实

对适用条款建立简短对应关系：要求来源 → 仿真实现位置与实际值 → 原始测量 → 判定方式。只落实本任务相关条件，不将准备工作无限扩展。

核对相关物体属性、机器人限制、接触设置、夹具或加载装置、测量接口、采样、时间基准及试次记录。数值由当前有效依据或明确的工程配置提供；不从旧对话补入未被采用的阈值。

无法等效实现、未经标定或模型能力不足的项目要明确标记。探索可以在用户明确接受的有限条件下进行，报告应限定适用范围；完整标准通过必须有完整的必要证据。
